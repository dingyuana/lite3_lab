# Lite3 实训考核与故障排查

## 学习目标

1. 按照可观察、可量化的标准完成个人与小组真机考核。
2. 用状态帧、速度、停车日志、标定残差与界面提示证明实验结果。
3. 按“先停车、再保活/扶稳、后定位链路、最后重试”的顺序处理故障。
4. 区分网络、状态机、运动轴、声纳、视频、标定、PID 与 GUI 问题。
5. 如实记录失败和未验证项，不绕过安全门控或修改代码制造“通过”。
6. 能解释 task04 历史缺失、task11 已并入 task12，并使用现行测试入口。

## 建议学时

建议 **2 学时**：考核说明与排障演练 0.5 学时，分组/个人考核 1 学时，复盘 0.5 学时。实操能力不足时，可增加 1 次补测；补测不压缩安全演示。

## 核心概念

### 证据链优于“看起来成功”

每个实验至少需要四类证据：

1. **输入**：运行命令、参数、机器人 IP、状态端口、现场状态。
2. **过程**：状态三元组、四膝、速度、声纳、界面提示或标定残差。
3. **结果**：动作完成判据、停车判据、退出后姿态。
4. **安全**：清场、扶稳、控制源唯一、停止口令和异常处理。

例如 task06 仅记录“脚本跑完了”不够；应记录点动速度峰值、停车后有效速度样本、forward 归零、收尾归零状态。

### 故障处理优先级

真机异常按以下顺序处理：

1. **停**：停止目标跟踪、松开方向键、发零轴；紧急时按实验室规程执行软急停、人工扶稳或物理断电。
2. **稳**：保持零值轴流或扶稳，确认机器人不会继续移动或突然失去支撑。
3. **读**：保存终端与界面提示原文，记录当前三元组和状态年龄。
4. **分**：判断是控制链路、状态链路、传感器、视频、标定还是 PID。
5. **修**：只改变一个变量；先离线验证，再从小运动量真机复测。
6. **记**：故障未解决或安全条件不足时，停止实验并报告教师。

### 现行边界

- task04 历史缺失，不布置补做。
- task11 已并入 task12；`legacy/task11_follow.py` 不参与安装、测试、评分和运行。
- task09 只验证前后左右平移，不包含偏航转向。
- task12 真机偏航方向必须单独验证；PID 自检不能替代真机方向测试。
- task08 的近障行为是停止 forward 并原地保持，不是自动绕障；其 `--cooldown` 当前未接入停车函数，实际观察上限为 5 s。
- task10 入口是真机控制；脱机视觉验证用 `task12_follow.py --offline`。

## 教师演示步骤

1. 公布评分量规、安全否决项、分组角色轮换和补测规则。
2. 展示一份合格记录：包含命令、状态、速度、停车、退出和异常原文；再展示一份只有“成功”的无效记录。
3. 演示 task07 停车失败日志，要求学生区分“方向正确”与“已停稳”。
4. 演示 task08 固定障碍触发，让学生识别“原地运动”和“自动避障”的差别。
5. 演示 task12 `--selfcheck`、`--offline --dummy-h` 和 dummy 真机拒绝，要求学生说明各模式边界。
6. 设置一个无真机运动风险的故障，例如状态端口被占用或 task12 使用 dummy 真机参数，让学生按排障表定位。
7. 演练一次停止流程：操作员停止输入，安全员扶稳，记录员保存提示，教师决定是否继续。
8. 按量规逐项打分，安全否决项单独记录原因，不用其他高分抵消。

## 学生实操步骤

### 考核前

1. 提交实验记录：每个任务的命令、参数、关键日志、结果判据、异常与退出姿态。
2. 完成个人口述准备：98、稳定站立、移动就绪、归零、死区、帧龄、看门狗、dummy 拦截。
3. 小组确认角色与轮换顺序，准备软急停终端。
4. 检查场地、悬挂/护架、线缆、电量、状态端口和控制源唯一性。
5. 从稳定趴下开始。若机器人姿态未知，先停止并报告教师，不直接起立。

### 考核中

1. 先完成 task01/task02 只读链路，再进入任何运动。
2. 基础项目由教师现场指定参数，学生先复述预期动作和停车条件，再执行。
3. 综合项目重点观察启动门控、方向符号、停车与退出，不以脚本运行速度评分。
4. 视觉项目先离线，再标定复核，最后悬挂真机验证；不得用 dummy 跑真机。
5. 出现方向反、状态丢失、停车失败、异常碰撞风险时，立即停止并记录，不连续重试。
6. 退出前停止跟踪、清空按键、按 Space 趴下，按考核要求归零并确认状态。

### 考核后

1. 关闭 GUI 和所有控制终端，确认没有残留心跳/轴流客户端。
2. 解除扶稳前确认机器人稳定趴下、无线缆缠绕、场地无遗留障碍。
3. 整理记录，标清“已验证、未触发、失败、由教师演示”四种结果。
4. 对每个失败项写出根因、处理动作和防止复发的方法。
5. 将单元测试结果作为逻辑验证证据，不把 unittest 通过写成真机验收通过。

## 验收标准

### 量化评分量规

总分 **100 分**，建议 80 分及格；安全否决项触发时，无论总分多少，本次真机考核记为“暂停/不通过”，整改后重测。

| 维度 | 分值 | 评分观察点 |
|---|---:|---|
| 安全操作与收尾 | 20 | 清场、扶稳、控制源、停止响应、最终姿态 |
| 协议与状态判读 | 15 | UDP、0901/0902、98、三元组、帧龄、归零 |
| 基础控制 | 20 | task01/02/03/05/06 的证据与判据 |
| 综合控制 | 15 | task07/08/09/10 的停车、方向、门控、互斥 |
| 视觉跟随 | 20 | 标定、离线、PID、安全、dummy、真机退出 |
| 记录与排障 | 10 | 命令、日志、根因、复盘、历史编号 |

每个维度按表现系数计分：

| 等级 | 系数 | 判断标准 |
|---|---:|---|
| 优秀 | 1.0 | 独立完成，证据完整，能解释失败与边界条件 |
| 良好 | 0.85 | 少量提示下完成，主要证据完整，能正确排障 |
| 合格 | 0.70 | 在教师分步指导下完成，结果有效，无安全违规 |
| 待补测 | 0.40 | 结果不完整、证据不足或关键概念错误 |
| 未完成 | 0 | 未执行、结果不可复现或主要任务失败 |

例如安全维度 20 分、表现“良好”，得 17 分；协议维度 15 分、表现“合格”，得 10.5 分。

### 安全否决项

出现以下任一行为，立即终止本次真机操作：

- 未清场、未扶稳或让人员进入机器人运动/夹伤路径。
- 同时运行多个控制客户端，或在方向反、停车失败后仍连续加大轴值/时长。
- 关闭状态监听、绕过启动门控或使用 dummy 矩阵进行真机跟随。
- 明知状态帧过期仍保持手动运动，或忽略 task09 缺状态时轴值不自动归零的风险。
- 用真人作为碰撞/避障测试目标。
- 发生异常后隐瞒、伪造日志，或在机器人仍运动/未稳定时离开。
- 把 `legacy/task11_follow.py` 作为安装、补考或真机运行入口。

## 故障排查总表

### 网络、端口与状态链路

| 故障现象 | 可能原因 | 诊断方法 | 处理 |
|---|---|---|---|
| task01 tx 增长但 rx=0 | 上报目标未指向本机、43897 占用、防火墙 | 检查端口绑定与机器人上报配置；运行 task02 | 停止运动实验，恢复状态链路后再继续 |
| ICMP 端口不可达 | 机器人控制端口无监听、IP 错、网络断开 | 核对默认 192.168.1.120:43893、供电与运控程序 | 不连续发运动命令试探；报告教师 |
| 状态端口绑定失败 | 另一个进程占用本地 UDP 端口 | 查看进程与端口占用；关闭冲突客户端 | 每台机器人同一时刻只保留一个控制源 |
| 状态时有时无 | 网络抖动、上报目标错误、端口冲突 | 比较 rx 计数是否持续增长、state_age 是否反复过期 | 先恢复稳定链路；运动中按安全停止处理 |
| `get_state()` 突然为 None | 未收到或帧龄超过 0.5 s | 查看累计 rx 计数与原始 state_age | 不把旧数据当实时数据，停止相关运动 |
| 有关节角度但无状态 | 0902 正常、0901 未到达 | 分别看 rx_count/joint_rx_count | task03 需要两者，先修 0901 |
| 98 被误报为故障 | 把 payload 首字段当 code | 查看 `(98,0,0)` 与公共状态表 | 按初始待机处理；首次起立要求电量高于 20% |

### 轴值、方向与停车

| 故障现象 | 可能原因 | 诊断方法 | 处理 |
|---|---|---|---|
| task06/07 未前进 | 轴值不大于 6553、未移动就绪、被阻挡、其他客户端覆盖 | 查看 gait、basic、轴值和速度 | 先排除状态与场地，再用默认点动参数 |
| 前进方向为负 | 轴符号/约定异常或另一控制源发负值 | 看 vel_body[0] 与命令来源 | 立即停止，报告教师，不盲目改符号 |
| task09 左移/右移速度符号不符 | 侧向约定或实测姿态干扰 | 对照 ±16000 与 vel_body[1] | 停止并记录；不在现场连续试错 |
| task09 状态丢失仍运动 | `_run_direction()` 无状态时只跳过采样 | 观察终端停止更新与当前轴值 | 立即 Ctrl-C/安全停止，恢复状态链路 |
| 停车后仍有速度 | 观察窗口不足、惯性、轴值残留、其他客户端 | 看停车日志与 cooldown | 保持零轴流，延长观察，排查控制源 |
| task06 显示“~方向正确” | 方向对但未停稳；函数仍可能返回 True | 单独核对停车段 | 不算完整通过，重新验证停车 |
| task06 停车样本为 None | 状态帧缺失 | 检查停车采样和 rx 计数 | 不能据 None 判停稳，重新获取有效数据 |
| task08 一直原地运动 | 前/后小于 1 m、非有限值或状态过期 | 查看前/后距离与模式切换日志 | 稳定后清障；检查传感器与状态帧 |
| task08 自动恢复前进 | 两侧距离均恢复到不小于 1.0 m | 查看“恢复”日志 | 确认场地仍安全，人员不进入路径 |
| task08 修改 cooldown 无变化 | 参数未传给 `_safe_stop()`，内部固定 5 s | 对照代码调用与停车日志 | 按实际 5 s 上限评价，不虚构参数效果 |
| 停车时直接停轴流 | 操作顺序错误 | 检查 forward=0 后是否仍发三轴 | 先零轴保活减速，再结束流 |

| 失焦后仍跟踪 | 窗口事件异常或会话未释放 | 查看跟踪按钮和状态 | Esc/停止按钮显式退出，关闭窗口复核 |

## 常见错误

- 只记录结果截图，不记录命令、参数和状态序列，导致无法复现。
- 将 task06 的部分成功、task08 的避障成功或进程退出码当作完整验收。
- 用增大轴值、延长时间、降低阈值来掩盖网络、标定或状态问题。
- 把 0.5 s 公共状态新鲜度、0.2 s 视觉帧龄、0.3 s 声纳帧龄、0.5 s 感知超时和 1.0 s 看门狗混为一谈。
- 将 task12 保留的 `lost_confirm=10` 字段误认为目标丢失会等待 10 帧；当前安全层立即停车。
- 认为 `--auto-follow` 会自动起立；它只自动发起跟踪，启动门控仍要求运动就绪。
- 认为离线模式能验证声纳保护；`--offline` 关闭真机声纳门控，只验证视觉与数值链路。
- 在标定后移动相机或机器人，却继续使用旧 H.npy。
- 用真人测试避障或跟随停车，造成碰撞风险。
- 把“单元测试通过”写成“真机安全通过”，忽略现场方向、场地和机械防护验证。
