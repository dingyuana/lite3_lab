课程与工程基础

学习目标

  • 说出四足机器人实验系统的五个基本环节。
  • 区分真机实验与仿真实验各自能验证的问题。
  • 使用“目标—约束—方案—验证”的工程流程完成一个小任务。
  • 理解为什么教学代码也要版本管理、测试和安全边界。

建议学时

2 学时，其中讲授 1 学时、小组讨论与实验设计 1 学时。

先修知识

基本 Python 语法、向量与三角函数初步知识。不需要预先掌握强化学习或 ROS2。

系统组成

四足机器人实验可拆成五个环节：

  1. 感知：关节编码器、IMU、超声波、相机、LiDAR。
  2. 状态估计：姿态、速度、位置、目标身份与地图。
  3. 决策：状态机、步态选择、PID、学习策略。
  4. 执行：电机力矩、关节位置目标、速度指令。
  5. 反馈：把执行结果再次送入感知与状态估计，形成闭环。

任何一环缺少时效性或符号约定，闭环都可能变成正反馈或失稳。

真机与仿真的分工

维度真机 task仿真 stage
主要目的验证协议、状态机、安全与真实动态验证算法、控制律、观测与系统接口
优势包含真实摩擦、冲击、延迟与硬件约束可重复、可加速、可注入故障
局限有跌倒和损坏风险，实验成本高模型误差可能导致“仿真成功、真机失败”
评价重点安全、稳定、可复现数值正确、边界完整、可解释

仿真不是真机的替代品。联合课程要求学生在相同坐标系和相同指令下比较两者，并解释差异来源。

工程流程

  1. 明确任务：例如“低速前进 3 秒并停稳”。
  2. 列出约束：空间、速度、轴死区、指令超时、急停方式。
  3. 设计状态序列：起立、移动模式、步态、前进、停车、趴下、归零。
  4. 选择可观测量：状态码、四膝角、线速度、位置、帧龄。
  5. 制定验收条件：方向正确、速度超过死区、停车窗口内停稳。
  6. 实施与记录：保存日志、参数、环境与异常现象。
  7. 复盘：区分代码错误、参数错误、环境错误和硬件错误。

教师演示

展示 task07 的完整状态序列。提问：如果停车后立即停止轴流，250 ms 超时会发生什么？引导学生认识到“归零”与“停稳”是两个不同事件。

学生活动

每组选择一个任务，填写一页设计卡：输入、输出、状态转换、安全约束、验收指标、失败后的收尾动作。

验收标准

  • 能完整绘制感知—决策—执行—反馈闭环。
  • 能列出至少三项真机与仿真的差异。
  • 设计卡中的验收条件可测量，不只写“机器人能动”。

思考题

  1. 为什么“代码运行无异常”不等于“机器人任务成功”？
  2. 如果仿真中前进方向正确，真机反向，应优先检查哪些环节？
  3. 状态机中的每个失败分支是否都需要安全收尾？
01

坐标与单位

学习目标

  • 正确读取机器人坐标系中的前后、左右和转向符号。
  • 区分角度制与弧度制、线速度与角速度、物理量与协议轴值。
  • 解释关节位置偏差和默认关节角在 RL 观测中的作用。
  • 识别正负号、单位换算和缩放系数导致的控制错误。

建议学时

2 学时，包含一次坐标方向核对练习。

先修知识

向量、基础三角函数和 Python NumPy。

坐标系

课程默认遵循右手系。描述方向时必须同时说明参考系：

  • pos_world：世界坐标系中的位置。
  • vel_body：机体坐标系中的速度；前进通常读取第 0 分量。
  • rpy：横滚、俯仰、偏航角。
  • 视觉标定：X 向右、Y 向前，原点为机器人地面投影。

不要把“图像坐标向右”直接当成“机器人向右”。Homography 的作用正是把像素坐标转换到地面米制坐标。

单位与范围

量课程常用单位注意事项
长度m超声波阈值 1.0 m、1.3 m
平面角rad 或 degPython 三角函数使用 rad
线速度m/s停稳阈值绝对值 <0.02
角速度rad/s转向需先确认符号
频率Hz30 Hz 周期约 33.3 ms
时间s超时、帧龄、稳定时间必须使用一致时钟

关节角与默认姿态

Lite3 有 12 个驱动关节。RL 部署课程按每条腿的 HipX、HipY、Knee 顺序构造 12 维向量，默认位置模式为：

(0.0, -0.65, 1.3) 重复 4 次

关节位置偏差为：

qpos - default_qpos

观测构造错误会直接改变策略输入，即使模型文件完全正确，也可能导致动作错误。

协议轴值

协议使用有符号 16 位轴值，速度与轴值之间需要缩放。课程中的前进、侧向、转向死区分别为：

forward: 6553
lateral: 12553
yaw:     9553

死区不是“建议值”，而是固件行为边界。很小的后退命令若直接截断为 0，会导致机器人不后退；task12 因此把非零小输出至少推到 deadzone + 1。

教师演示

运行 task12 的 --selfcheck，展示反向后输出越过前进死区。再展示零值不会被补偿成死区，避免静止时蠕动。

学生活动

给定 vx=-0.2 m/s、fwd_scale=20000，手算原始轴值并提出安全补偿方法。使用 Python 验证结果。

验收标准

  • 所有数值都带单位。
  • 能解释世界坐标与机体坐标的区别。
  • 能正确构造 12 维默认关节向量。
  • 能说明为什么零轴值不能做死区补偿。

思考题

  1. 偏航角与偏航角速度有什么区别？
  2. 如果策略输出被当作目标角度直接写入电机 data.ctrl，会产生什么问题？
  3. 图像标定中四个点的顺序为什么必须一致？
02

通信与实时系统

学习目标

  • 解释 UDP 命令帧和状态帧的基本结构。
  • 理解心跳、轴流频率、帧龄和指令超时的作用。
  • 区分“收到过数据”和“数据仍然新鲜”。
  • 根据丢包、延迟和超时设计安全降级。

建议学时

2 学时。

先修知识

网络字节序、IP 地址、端口和线程基础。

Lite3 通信模型

运动命令发往机器人 43893 端口，本机监听 43897 接收状态。命令头为 12 字节：

command_code : uint32
parameter    : uint32
sequence     : uint32

使用小端格式 <III。0x0901 是机器人状态帧，0x0902 是关节数据帧。状态码如 (1,0,0) 表示趴下，(6,0,0) 表示力控站立；98 是初始待机，不代表已经归零。

实时性

实时控制不是“线程越多越好”，而是每个周期能否在期限内产生有效输出。

  • 心跳 5 Hz：维持连接与底层保活。
  • 轴流 30 Hz：持续发送前进、侧向、转向三个轴。
  • 轴流必须 ≥20 Hz：低于该频率可能触发约 250 ms 的指令超时。
  • 视频跟踪：感知频率可以低于控制频率，但必须检查帧龄。

帧龄

帧龄是“当前时刻减去数据产生时刻”，不是“当前时刻减去程序读取时刻”。

错误做法是每次读取状态都把超声波时间戳刷新为当前时间，这会让已经停止上报的旧数据永远看起来新鲜。正确做法是保留原始状态帧的接收时间，再计算：

age = now - original_receive_time

安全降级

链路异常时，安全降级顺序通常为：

  1. 停止增加新动作。
  2. 清空 PID 积分与上一帧动作。
  3. 发送零轴值并保持轴流。
  4. 等待速度下降到停稳阈值。
  5. 根据任务状态选择趴下或归零。

task12 还使用独立看门狗。即使 YOLO 推理线程卡住，另一个线程也能在 1.0 s 无更新时停车。

教师演示

打开 task02 的状态输出，记录状态帧率；随后断开状态监听，观察数据年龄和运动拒绝逻辑。讨论“显示继续刷新”与“数据继续新鲜”的区别。

学生活动

测量 30 Hz 轴流的实际周期，计算周期抖动。人为停止视频帧更新，验证看门狗是否在设定时间内停车。

验收标准

  • 能解释 5 Hz 心跳与 30 Hz 轴流的不同职责。
  • 能区分数据读取时刻与数据产生时刻。
  • 能设计至少两级超时：普通异常停车、严重链路异常退出跟踪。

思考题

  1. 为什么 UDP 没有可靠重传也能用于周期控制？
  2. 看门狗为什么应独立于推理线程？
  3. 如果心跳正常但状态帧停止，哪些安全功能应失效？
03

安全与实验规范

学习目标

  • 执行真机实验前后的安全检查。
  • 识别起立、移动、视觉跟踪和归零的高风险环节。
  • 正确使用软急停和悬挂/防跌倒装置。
  • 为仿真扰动实验设置边界，避免把仿真参数直接搬到真机。

建议学时

2 学时，安全考核不合格不得进入真机运动实验。

先修知识

课程导学与基本电机控制概念。

真机安全门

每次运动实验前至少确认：

  1. 机器人电量满足要求；初始待机 98 且电量 ≤20% 时禁止首次起立。
  2. 悬挂或防跌倒装置可靠，人工扶稳人员知道何时撤离。
  3. 前方、后方至少留 2 m，侧面空间人工确认。
  4. 地面平整、干燥，线缆不缠绕腿部。
  5. 状态监听正常，能看到 0x0901 与 0x0902。
  6. 软急停命令可立即执行。
  7. 同一时间只有一个人发送运动指令。

起立验收

不能只看状态码。课程要求同时满足：

  • 状态为 (6,0,0)。
  • 四膝均值在 60°~90°。
  • 连续稳定 3 秒。

如果状态码变化但姿态不满足，应视为未完成，不应继续前进。

停车验收

发送零轴值只是停车过程的开始。必须保持轴流并观察 abs(vel_body[0]) < 0.02 m/s。在观察窗口内未停稳，应记录失败并检查步态、地面、轴值和外部阻挡。

视觉跟踪安全

  • 首次跟踪必须悬挂验证转向符号。
  • 使用真实 Homography，dummy 矩阵严禁真机。
  • 目标丢失、帧过期、感知超时、超声波超时都应停车。
  • 视觉距离过近只允许转向，过远则放弃目标。
  • 手动控制与跟踪互斥，切换时先停运动。

归零

归零会写固件零位偏移，不能随意重复。课程流程是先趴下，确认四膝进入趴下姿态，再发送 0x21010C05，等待 (17,0,0) 后回到趴下。

仿真安全

仿真允许切换重力、摩擦和施加 150 N 推力，但这些属于教学扰动，不是真机推荐参数。仿真实验应保存参数，使用重置功能恢复初始状态，并避免在模型未站稳时连续施加外力。

教师活动

进行 5 分钟安全口头考核。随机给出“状态 98 电量 18%”“超声波停止更新”“停车速度仍 0.05”等情境，要求学生给出下一步动作。

学生活动

每组完成安全检查表并签名。任何一项不通过，只允许运行只读 task01/task02 或仿真课程。

验收标准

  • 能完整复述软急停操作。
  • 能区分起立、停车和归零的验收条件。
  • 能列出视觉跟踪的五类停车触发条件。

思考题

  1. 为什么软急停不能替代悬挂和空间检查？
  2. 如果归零后仍不是 (1,0,0)，能否继续起立？
  3. 仿真中成功的推力实验，搬到真机前需要哪些额外验证？
04

调试与科学记录

学习目标

  • 用可复现日志描述实验，而不是只记录“能动/不能动”。
  • 使用故障树定位协议、状态机、控制参数和环境问题。
  • 设计单变量对照实验。
  • 按要求提交实验报告与证据。

建议学时

2 学时。

先修知识

Python 运行与基础统计。

最小记录集

每次实验至少记录：

  • 日期、设备/软件版本、Git 提交或文件版本。
  • 机器人 IP、状态端口、视频地址。
  • 任务入口和完整命令参数。
  • 地面、空间、电量、是否悬挂。
  • 状态码、四膝、速度、位置、帧龄等观测。
  • 异常发生时刻、日志和最终收尾状态。

只写“前进失败”无法复现；应写“forward=9000、持续 3 s、vel 峰值 0.003、状态保持 (6,0,0)、前方无障碍”。

故障树

以“机器人不前进”为例：

  1. 是否收到新鲜状态帧？否则检查网络、端口和接收线程。
  2. 是否处于移动模式且步态正确？否则检查状态机。
  3. 是否站立稳定、四膝合理？否则先解决姿态。
  4. 轴值是否越过死区？否则调整速度映射。
  5. 是否有超声波拦截？否则检查距离与数据龄。
  6. 是否有外部阻挡或地面打滑？否则进行环境对照。

每次只改变一个变量，避免同时调速度、PID、步态和标定。

数值检查

  • 重力投影：水平姿态应接近 (0,0,-1)。
  • PD 力矩：目标为零、当前位置为正时应产生负力矩。
  • 观测维度：3+3+3+12+12+12=45。
  • 轴死区：非零小输出越过边界，零输出仍为零。
  • 停车：观察窗口结束后速度必须低于阈值。

教师演示

故意把 --cooldown 设置为很短值，展示 task07 不会把“未停稳”误报为成功。再展示日志如何区分方向失败与停车失败。

学生活动

两人一组记录同一实验，交换日志后仅凭记录复现命令并预测结果。无法复现的项目回到记录中补充证据。

验收标准

  • 报告包含完整命令、参数和观测数据。
  • 至少进行一次单变量对照。
  • 故障结论有证据支持，不把猜测写成根因。
  • 所有真机实验都有收尾状态记录。

思考题

  1. 为什么速度峰值和位移不能互相替代？
  2. 如果仅修改 PID 后现象消失，能否直接认定 PID 是唯一根因？
  3. 哪些日志字段在真机事故复盘中最重要？
