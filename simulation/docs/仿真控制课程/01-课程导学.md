# Lite3 大学生实训项目仿真课程导学

## 课程定位与使用方式

本课程以 `~/lite3_lab/simulation` 中的 Lite3 四足机器人仿真代码为主线，按照“物理基础 → 双引擎实验 → 强化学习部署 → ROS2 控制 → LiDAR 数据前端 → 综合考核”的顺序展开。课程只使用仿真环境，不连接真实机器人。

Windows 可通过 `\\wsl.localhost\<发行版>\home\<用户>\lite3_lab\simulation` 访问同一目录，但 PyBullet、MuJoCo、ONNX Runtime 和 ROS2 实验应在 WSL 中运行。ROS2 实验需先 source 对应发行版及 `drdds` 消息包所在的工作空间；`pip install -r requirements.txt` 不能替代 ROS2 安装。

| 阶段 | 主要入口 | 学生应形成的认识 |
|---|---|---|
| stage1 | `stage1_pybullet.py` | URDF、接触、位置控制、开环步态与外力扰动 |
| stage2 | `stage2_mujoco_lab.py` | MJCF、PD 力矩、摩擦/重力切换与安全蹲伏 |
| stage3 本地策略 | `stage3_mujoco_rl.py` | ONNX 策略、45 维观测、默认关节角与电机力矩 |
| stage3 ROS2 | `stage3_mujoco_ros2_sim.py` | 关节指令校验、MIT 参数与超时零力矩 |
| stage4 | `stage4_ros2_keyboard.py`、`stage4_ros2_walk_sim.py`、`stage4_ros2_controller.py` | `/cmd_vel` 到 `/JOINTS_CMD` 的控制链 |
| stage5 | `stage5_lidar_frontend_sim.py` | LiDAR 点云、真值里程计与 TF 数据前端 |

> stage5 只是 LiDAR/SLAM 数据前端。它发布仿真真值里程计和真值 TF，不执行建图、定位、扫描匹配或回环，也没有发布 SLAM 估计结果。

## 学习目标

完成课程后，学生应能够：

1. 说明 URDF/MJCF、仿真步长、接触模型、关节坐标和电机执行器在四足机器人实验中的作用。
2. 使用 `project_paths.py` 定位模型与 ONNX 策略，不依赖个人绝对路径。
3. 操作 stage1 与 stage2，比较 PyBullet 位置控制和 MuJoCo PD 力矩控制的差异。
4. 推导 `R^T*(0,0,-1)` 的物理意义，并正确解释 stage3 的 45 维观测顺序。
5. 按部署策略使用默认关节角 `(0,-0.65,1.3)`，解释 PD 力矩为何不能直接替换成目标角度。
6. 描述 ROS2 的 `/JOINTS_CMD` 校验规则、MIT 力矩公式和 0.5 秒无新指令后的零力矩行为。
7. 跟踪 stage4 的话题与频率，区分键盘停止、控制器停止和仿真器超时保护。
8. 识别 stage5 的点云、真值里程计、TF 与 Marker，并说明其与 SLAM 估计的边界。
9. 根据日志、话题和测试结果定位常见故障，形成可复核的实验记录。

## 先修知识

- **Python 基础**：能运行脚本、阅读函数、使用虚拟环境，并理解 NumPy 数组形状与索引。
- **数学基础**：理解向量、矩阵乘法、转置、旋转矩阵、四元数和弧度制。
- **物理基础**：理解重力、摩擦力、速度、力矩和 PD 反馈的基本含义。
- **机器人基础**：了解四足机器人腿部关节、姿态、步态和底盘坐标系。
- **Linux/WSL 基础**：会切换目录、激活虚拟环境、查看文件和使用多个终端。
- **ROS2 基础（stage3 ROS2 起需要）**：了解节点、话题、消息、TF、`rclpy` 和 source 环境。

不要求预先掌握强化学习算法。本课程重点是“给定训练好的 ONNX 策略，在仿真中正确部署”，不是从零训练 PPO。

## 核心概念

### 从模型到执行的完整链路

每章都围绕同一条链路检查问题：

```text
模型文件 → 仿真状态 → 观测/控制器 → 策略或目标姿态 → 执行器力矩 → 下一仿真状态
```

例如 stage3 中，模型状态先构造 45 维观测，ONNX 输出 12 维动作；动作用于生成目标关节角，再由 PD 公式转成 12 维力矩，最后写入 `data.ctrl`。任何一层使用了错误的坐标、关节顺序或单位，后一层即使代码“能运行”，结果也会错误。

### 资源定位与项目边界

`project_paths.py` 以该文件自身位置为基准向上找到项目根目录，并定位：

- URDF：`Lite3_rl_deploy/third_party/deep_robotics_model/Lite3/Lite3_urdf/urdf/Lite3.urdf`
- MJCF：`Lite3_rl_deploy/third_party/deep_robotics_model/Lite3/Lite3_mjcf/mjcf/Lite3.xml`
- ONNX：`Lite3_rl_deploy/policy/ppo/policy.onnx`

因此，模型和策略应位于 `simulation` 的同级项目目录中。`assets/generated/` 是历史生成文件，不参与课程运行。复制脚本时不要只复制 `.py` 文件而丢失同级模型目录。

### 各阶段不能混用的“标准姿态”

| 阶段 | HipX | HipY | Knee | 说明 |
|---|---:|---:|---:|---|
| stage1 站立/trot | 左侧 `0.1`，右侧 `-0.1` | `-0.985` | `2.084` | PyBullet 位置控制目标 |
| stage2 站立 | 左侧 `0.1`，右侧 `-0.1` | `-0.7` | `1.2` | MuJoCo 实验站姿 |
| stage2 安全蹲伏 | 左侧 `0.1`，右侧 `-0.1` | `-1.5` | `2.6` | 降低重心 |
| stage3 部署默认角 | `0.0` | `-0.65` | `1.3` | ONNX 策略的动作中心 |
| stage4/stage5 步态 | 左侧 `0.1`，右侧 `-0.1` | `-0.985` | `2.084` | 脚本式步态基础站姿 |

这些数值对应不同实验设计，不能因为“都是站立”就相互替换。尤其不能把 stage1 的 `(0.1,-0.985,2.084)` 当作 stage3 的默认关节角。

### 数据真值与算法估计

仿真器直接知道的位姿称为“真值”。SLAM 根据传感器数据估计的位姿称为“估计值”。stage5 发布的是前者，目的是给外部 SLAM 提供输入和评测参照，不是让学生误以为已经实现了 SLAM。

## 教师演示

### 演示 1：环境与资源检查

在 WSL 终端执行：

```bash
cd ~/lite3_lab/simulation
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
ls ../Lite3_rl_deploy/policy/ppo/policy.onnx
python3 -m unittest discover -s tests -v
```

演示重点：

1. `project_paths.py` 如何从脚本位置推导资源路径。
2. 单元测试只导入 NumPy 与 stage3 辅助函数，不打开 MuJoCo 窗口。
3. 6 个测试覆盖重力投影、默认关节角、PD 力矩、限幅和观测构造。
4. ROS2 依赖需另行安装并 source；安装失败时不应通过伪造 pip 包绕过。

### 演示 2：建立阶段对照表

依次启动 stage1、stage2、stage3，只观察并记录，不立即追求“走得远”。让学生指出三个脚本在以下方面的差异：

- 输入方式：PyBullet 窗口键、终端字母、终端字母。
- 控制方式：位置控制、PD 计算后写 `data.ctrl`、ONNX+PD 写 `data.ctrl`。
- 默认角、推力持续时间、反馈信息。

### 演示 3：画出 stage5 的数据边界

在白板上画出：

```text
MuJoCo 真值状态 ──→ /ground_truth_odom
                 ├─→ TF: world → base_link
                 └─→ /lidar_points（世界系点云）
                               ↓
                     外部 SLAM（本课程未实现）
```

强调箭头方向：stage5 向外部系统提供数据，不接收 SLAM 估计，也不构建地图。

## 学生实操

1. 在 WSL 中完成虚拟环境安装，记录 Python、NumPy、PyBullet、MuJoCo、ONNX Runtime 版本。
2. 核对三个资源文件存在，并运行 `python3 -m unittest discover -s tests -v`。
3. 从 `simulation` 目录依次运行 stage1、stage2、stage3，各完成一次启动、复位和退出。
4. 填写阶段对照表：输入键、默认角、控制量、推力、复位行为、主要日志。
5. 画出 stage3 的观测—动作—力矩链路，标注每一段数组的维数。
6. 画出 stage5 的发布话题和坐标系，并用一句话写明“它不做什么”。
7. 保存关键终端输出或截图，作为后续验收证据；不要修改模型或策略文件。

> Windows 资源管理器适合阅读本课程 Markdown 与源码，但带有交互终端、ROS2 和 WSLg 的实验应从 WSL 终端启动。

## 思考题

1. 为什么资源路径要基于 `__file__`，而不是写死 `/home/<用户名>`？
2. 如果 45 维观测中各段长度正确但顺序错误，ONNX 推理还能运行吗？结果为何仍可能错误？
3. 为什么 stage1 的默认角不能直接替代 stage3 的默认角？
4. 位置目标与电机力矩有什么本质区别？
5. 仿真真值里程计能否作为 SLAM 的定位精度指标？它能否替代 SLAM 估计？
6. 键盘停止 `/cmd_vel`、控制器停止发布 `/JOINTS_CMD`、仿真器超时零力矩分别发生在哪一层？

## 常见错误

- **在 Windows PowerShell 中直接运行全部实验**：ROS2、`termios` 和 WSL 图形环境可能不可用。应在 WSL 中运行。
- **只复制 `simulation` 目录**：缺少 `Lite3_rl_deploy` 后模型或策略无法加载。应保留项目相对结构。
- **把 pip 依赖当作完整 ROS2 环境**：`drdds`、`rclpy` 等需要正确的 ROS2 安装与 source。
- **混淆各阶段默认角**：先确认脚本，再讨论数值；不要跨阶段复制“站姿参数”。
- **把 stage5 称为 SLAM**：准确名称是“使用真值里程计的 LiDAR/SLAM 数据前端仿真”。
- **遇到 GUI 问题只重装 Python 包**：先检查 WSLg、`DISPLAY`、图形驱动与是否从交互式终端启动。
- **忽略复位的环境恢复作用**：stage1/stage2 的复位会同时恢复摩擦、重力、模式和推力状态，不能把复位理解为只移动机器人。
