# Lite3 强化学习部署实验

## 学习目标

完成本单元后，学生应能够：

1. 说明本实验部署的是训练好的 PPO ONNX 策略，而不是在课程中重新训练策略。
2. 按顺序、缩放和数据类型正确构造 45 维观测。
3. 解释 `R^T*(0,0,-1)` 投影重力为何能向策略提供机身倾斜信息。
4. 正确使用部署默认关节角 `(0,-0.65,1.3)` 和动作缩放 `0.25`。
5. 将 12 维策略动作转换为目标关节角，再用 `kp=30`、`kd=1` 计算并限幅电机力矩。
6. 描述 ROS2 关节指令的数量校验、数值解析、有限值校验和 0.5 秒超时零力矩。
7. 区分“策略部署”“脚本步态”“MIT 参数下发”和“真实机器人控制”。

## 核心概念

### 部署链路与控制周期

`stage3_mujoco_rl.py` 每个仿真步执行以下链路：

```text
读取 qpos/qvel
  → 计算机体系投影重力
  → 拼接 45 维观测
  → ONNX 输出 12 维动作
  → target = default + 0.25 * action
  → tau = PD(target, qpos, qvel) 并按执行器范围限幅
  → data.ctrl = tau
  → mj_step
```

策略通过 ONNX Runtime 的 `CPUExecutionProvider` 运行。脚本读取 ONNX 输入维度，若不是 45 会直接报错，避免在错误输入形状下继续推理。

### 45 维观测的精确顺序

`build_observation()` 按以下顺序拼接，最终类型为 `float32`、形状为 `(45,)`：

| 切片索引 | 内容 | 维数 | 缩放/处理 |
|---|---|---:|---|
| `obs[0:3]` | 机身角速度 | 3 | 乘以 `0.25` |
| `obs[3:6]` | 机体系投影重力 | 3 | 不缩放 |
| `obs[6:9]` | 速度指令 `[vx,vy,vaw]` | 3 | 不缩放 |
| `obs[9:21]` | 关节位置偏差 `q-default` | 12 | 不缩放 |
| `obs[21:33]` | 关节速度 | 12 | 乘以 `0.05` |
| `obs[33:45]` | 上一帧动作 | 12 | 不缩放 |

维度合计：

```text
3 + 3 + 3 + 12 + 12 + 12 = 45
```

“上一帧动作”指上一轮 ONNX 输出的原始动作，不是目标角，也不是已经限幅的力矩。初始化与复位时该数组为 12 维零向量；当前帧先构造观测，推理返回后才把 `action` 更新为新结果。

各段长度由 `expected_sizes=(3,3,3,12,12,12)` 检查。即使总长度碰巧为 45，只要某一段长度错误，也应视为观测构造错误。

### 投影重力：`R^T*(0,0,-1)`

策略不能直接读取“世界系重力”，而需要知道重力相对机身的方向。设 `R` 是机体系到世界系的旋转矩阵，则：

```text
g_body = R^T * g_world_direction = R^T * (0,0,-1)
```

两个必须掌握的结果：

- 机身水平、四元数为 `[1,0,0,0]` 时，`g_body=[0,0,-1]`。
- 绕 x 轴 `+90°`、四元数为 `[sqrt(0.5),sqrt(0.5),0,0]` 时，`g_body=[0,-1,0]`。

它让策略在身体侧倾、俯仰或翻滚时获得姿态相关信号。投影重力只是姿态线索之一，不能单独代替完整状态。

### 默认关节角与动作缩放

部署策略的默认模式为：

```text
DEFAULT_JOINT_PATTERN = [0.0, -0.65, 1.3]  # HipX, HipY, Knee
default_qpos = [0.0,-0.65,1.3] × 4
```

结合 stage4 的编号约定，四组为 FL、FR、HL、HR；stage3 的实际读取仍由模型执行器与关节地址决定。动作与目标位置的关系为：

```text
target_qpos = default_qpos + ACTION_SCALE * action
ACTION_SCALE = 0.25
```

例如默认角为 `-0.65`、策略输出该关节动作为 `0.4`，则目标角为：

```text
-0.65 + 0.25*0.4 = -0.55
```

这不是把实际关节角增加 `0.4`，也不是直接令电机输出 `0.4 N·m`。

> 不能使用 stage1/stage4 的 `HipY=-0.985`、`Knee=2.084` 替换 stage3 的部署默认角。策略的观测偏差和动作中心都建立在 `(0,-0.65,1.3)` 上。

### PD 力矩，而不是目标角度

`Lite3.xml` 的执行器是电机，stage3 的 `data.ctrl` 需要力矩：

```text
tau = 30*(target_qpos-qpos) + 1*(0-qvel)
```

随后按每个执行器的 `model.actuator_ctrlrange` 逐元素裁剪。

需要区分三个数组：

| 数组 | 含义 | 是否直接写入 `data.ctrl` |
|---|---|---|
| `action` | ONNX 原始输出 | 否 |
| `target_qpos` | 默认角加缩放动作 | 否 |
| `tau` | PD 计算并限幅后的力矩 | 是 |

### 本地键盘指令与复位

| 键 | 作用 |
|---|---|
| `w` | `cmd_vx=0.6` 前进 |
| `s` | `cmd_vx=-0.4` 后退 |
| `a` | `cmd_vyaw=0.6` 左转 |
| `d` | `cmd_vyaw=-0.6` 右转 |
| `x` | `cmd_vx` 与 `cmd_vyaw` 清零 |
| `p` | 触发侧向 150 N 推力 |
| `r` | 重置模型数据、默认关节角、高度和动作 |
| `q` | 退出 |

速度指令为 `[cmd_vx,cmd_vy,cmd_vyaw]`；本地键盘不会设置 `cmd_vy`，它始终保持 0。`w/s` 与 `a/d` 可以组合，`x` 同时停止线速度和转向。

**重要细节：`r` 不复零速度指令。** 它重置 `action` 和推力标志，但当前 `cmd_vx/cmd_vyaw` 保留。若希望复位后静止，应先按 `x`，再按 `r`。

### ROS2 仿真：消息、校验与 MIT 力矩

`stage3_mujoco_ros2_sim.py` 提供：

- 订阅 `/JOINTS_CMD`，消息类型为 `drdds.msg.JointsDataCmd`。
- 发布 `/JOINTS_DATA`，消息类型为 `drdds.msg.JointsData`。
- 每个关节指令字段顺序为 `[kp,kd,position,velocity,torque]`。

接收端依次检查：

1. `len(joints_data) == model.nu`，当前应为 12；
2. 能转换为 `float64` 数值矩阵；
3. 所有字段都是有限值，即不含 `NaN` 或 `Inf`。

只有全部通过，才在锁保护下替换命令并更新时间戳。**无效指令不会覆盖上一条有效指令，也不会刷新时间戳。**

有效命令下发的力矩为：

```text
tau = kp*(position-q) + kd*(velocity-dq) + torque
```

这与本地 stage3 固定 `kp=30`、`kd=1`、速度目标为 0 的路径不同；ROS2 仿真允许命令携带增益、位置目标、速度目标和前馈力矩。

当前代码只校验“关节数量、可解析性、有限值”，**不校验增益、位置、速度或力矩是否超出安全幅值**；ROS2 路径也没有调用本地 `pd_torque_control()` 的 `ctrlrange` 限幅。有限值合法不等于控制安全。

### 0.5 秒超时与状态发布

仿真器使用 `time.monotonic()` 记录最近一次**有效**命令时间：

```text
elapsed = now - last_valid_command_time
若 elapsed > 0.5 s：tau = 全零
否则：按 MIT 公式计算 tau
```

- 节点启动时就初始化时间戳，因此即使从未收到命令，也会在约 0.5 秒后进入零力矩状态。
- 正好等于 0.5 秒不必然触发，代码条件是严格大于 `0.5`。
- 无效消息持续到达不能“保活”；时间戳只对有效消息更新。
- 发布者停止后，最后一帧力矩最多被保持到超时判定，然后输出零力矩。
- `/JOINTS_DATA` 每 5 个仿真步发布一次，包含 12 个关节的位置和速度；主循环每次睡眠约 `0.002 s`。

零力矩是安全失效保护，不会让机器人自动恢复默认站姿；在重力作用下机器人可能下沉或摔倒。

### `stage3_ros2_node.py` 的当前状态

该文件的有效代码整体处于注释状态，没有可运行的节点 `main`。它保留了一段纯力矩正弦实验的历史草稿，**不能作为当前 ROS2 控制入口**。课程应使用：

```text
stage3_mujoco_ros2_sim.py（仿真）
+ stage4 的指令节点（命令来源）
```

1. 为什么策略输入关节位置偏差，而不是直接输入绝对关节角？

## 常见错误

- **把观测段顺序写错但只检查总长度**：ONNX 可能仍接受输入，但策略语义完全错误。
- **把角速度或关节速度的缩放漏掉**：分别是 `0.25` 和 `0.05`。
- **把动作当作已经乘过 `0.25`**：目标角计算时才乘动作缩放。
- **沿用 stage1/2 的默认角**：stage3 固定使用 `(0,-0.65,1.3)`。
- **把 `target_qpos` 直接写入 `data.ctrl`**：该执行器需要力矩。
- **只写比例项、漏掉速度阻尼**：会改变动态响应并可能导致振荡。
- **误以为 `r` 会清除速度命令**：应先 `x` 再 `r`。
- **用 `stage3_ros2_node.py` 启动实验**：文件整体被注释，没有有效运行入口。
- **把非法消息到达当作“仍在线”**：只有有效命令更新时间戳。
- **把 0.5 秒超时理解为固定关闭电机电源**：代码是在仿真主循环输出全零力矩。
- **认为有限值检查就是安全限幅**：当前 ROS2 路径没有幅值检查和 `ctrlrange` 裁剪。
- **忽略 ROS2 source**：`rclpy` 或 `drdds` 导入失败通常与工作空间环境有关，不应修改课程脚本绕过。
