# 调试与科学记录

## 学习目标

- 用可复现日志描述实验，而不是只记录“能动/不能动”。
- 使用故障树定位协议、状态机、控制参数和环境问题。
- 设计单变量对照实验。
- 按要求提交实验报告与证据。

## 建议学时

2 学时。

## 先修知识

Python 运行与基础统计。

## 最小记录集

每次实验至少记录：

- 日期、设备/软件版本、Git 提交或文件版本。
- 机器人 IP、状态端口、视频地址。
- 任务入口和完整命令参数。
- 地面、空间、电量、是否悬挂。
- 状态码、四膝、速度、位置、帧龄等观测。
- 异常发生时刻、日志和最终收尾状态。

只写“前进失败”无法复现；应写“forward=9000、持续 3 s、vel 峰值 0.003、状态保持 (6,0,0)、前方无障碍”。

## 故障树

以“机器人不前进”为例：

1. 是否收到新鲜状态帧？否则检查网络、端口和接收线程。
2. 是否处于移动模式且步态正确？否则检查状态机。
3. 是否站立稳定、四膝合理？否则先解决姿态。
4. 轴值是否越过死区？否则调整速度映射。
5. 是否有超声波拦截？否则检查距离与数据龄。
6. 是否有外部阻挡或地面打滑？否则进行环境对照。

每次只改变一个变量，避免同时调速度、PID、步态和标定。

## 数值检查

- 重力投影：水平姿态应接近 `(0,0,-1)`。
- PD 力矩：目标为零、当前位置为正时应产生负力矩。
- 观测维度：3+3+3+12+12+12=45。
- 轴死区：非零小输出越过边界，零输出仍为零。
- 停车：观察窗口结束后速度必须低于阈值。

## 教师演示

故意把 `--cooldown` 设置为很短值，展示 task07 不会把“未停稳”误报为成功。再展示日志如何区分方向失败与停车失败。

## 学生活动

两人一组记录同一实验，交换日志后仅凭记录复现命令并预测结果。无法复现的项目回到记录中补充证据。

## 验收标准

- 报告包含完整命令、参数和观测数据。
- 至少进行一次单变量对照。
- 故障结论有证据支持，不把猜测写成根因。
- 所有真机实验都有收尾状态记录。

## 思考题

1. 为什么速度峰值和位移不能互相替代？
2. 如果仅修改 PID 后现象消失，能否直接认定 PID 是唯一根因？
3. 哪些日志字段在真机事故复盘中最重要？
