# Lite3 基础控制实验

## 学习目标

本单元覆盖 task01、task02、task03、task05、task06。完成后学生应能够：

1. 验证 UDP 双向链路，读取状态帧、关节帧和基本遥测。
2. 按状态机完成起立、稳定站立、趴下和归零，并给出每一步成功证据。
3. 区分稳定站立与移动就绪，正确切换移动模式和低速步态。
4. 完成一次短时前进点动，验证前向死区和停车效果。
5. 根据终端日志识别“未动、方向反、未停稳、归零未确认”等不同结果。

## 建议学时

建议 **8 学时**：

| 任务 | 演示/讲解 | 分组实操 | 建议 |
|---|---:|---:|---:|
| task01 心跳与链路 | 0.5 | 0.5 | 1 |

| task03 起立到归零 | 1 | 2 | 3 |
| task05 移动模式与低速步态 | 0.5 | 1 | 1.5 |

## 核心概念

### 基础流程的共同结构

task03/05/06 共享以下教学结构，但细节不同：

1. 建立控制器，启动 5 Hz 心跳与状态/关节接收。
2. 确认遥测就绪，判断当前是否已经稳定站立。
3. 需要起立时发送 `0x21010202`，等待 `(6,0,0)` 且四膝均值 60°～90°连续 3 s。
4. task05/06 再切 `0x21010D06` 移动模式，启动默认 30 Hz 的三轴零值流，发送 `0x21010300` 低速步态。
5. 移动准备成功判据为 `basic=6`、`gait=0`、四膝均值 60°～130°。
6. 执行本任务的观察或点动。
7. 运动轴归零，维持轴流减速，再趴下；默认收尾调用 `ensure_home()`。

**这些脚本每次都从自己的启动流程重新判断姿态**，不会自动继承上一个脚本的移动模式。上一个脚本已归零并趴下，是下一次真机运行最稳妥的起点。

### 站立与移动就绪不是同一件事

- task03 的“稳定站立”是 `(6,0,0)` 与四膝 60°～90°连续 3 s。
- task05/06 的“移动就绪”接受 `basic=6`、`gait=0`、四膝 60°～130°；既可能是 `(6,0,0)`，也可能是 `(6,0,1)` 半蹲踏步态。
- 起立阶段发送轴指令会改变姿态，可能进入移动就绪半蹲。因此不能一边等待 task03 的稳定站立判据，一边试探轴值。

### task06 的两个独立判据

- 方向：点动期间前向速度峰值大于 `0.02 m/s`。
- 停车：停车观察期间前向速度峰值小于 `0.02 m/s`。

代码的返回逻辑需要特别注意：

- 点动期间没有状态样本时，方向判据失败。
- 停车期间没有状态样本时，`vel_after_peak is None` 也被代码当作停稳。
- 停车判据使用有符号的 `max(vel_samples)`，不是绝对峰值；大幅负速度不能被这个条件排除。
- 当方向正确但停车未停稳时，函数仍可能返回 `True`，终端结论为“~方向正确，但停车后未完全停稳”。

因此，**学生验收不得只看进程退出码或“全流程成功”字样**，必须查看方向、停车和归零三段日志。

## 教师演示步骤

1. 在趴下状态运行 task01，先展示发送与状态接收，再运行 task02 展示关节明细。
2. 讲解 98 初始待机与 `(6,0,0)` 的区别，强调状态数据是动作确认的依据。
3. 在悬挂/护架下运行 task03，逐阶段指出日志中的“起立成功”“保持结束”“趴下”“观察到 17”“回到 1”。
4. 说明 task03 当前实现没有独立的“启动前归零”步骤，尽管 `--no-home` 的帮助文本使用过时措辞；它只跳过收尾归零。
5. 运行 task05，让学生观察切移动模式后姿态从站立变为允许的半蹲就绪态，而 forward 始终为零。
6. 运行 task06 的一次短点动，记录 forward 从 0 到 7000、再回 0 的时间线和速度变化。
7. 用参数拒绝演示死区：在趴下状态运行 `task06_axis_tap.py --value 6553`，程序应在建立运动流程前拒绝；不要用低于死区的大时长试探。
8. 展示一次“有方向、未停稳”的日志判读方式，提醒学生不能把部分成功当作全部通过。

## 学生实操步骤

### task01：心跳保活与双向链路

**目标**：确认本机发送心跳且收到机器人状态帧，区分 UDP 发送与双向通信。

**教师演示要点**

```bash
python3 task01_heartbeat.py --duration 10
```

指出日志中的发送心跳、接收状态、关节帧和状态三元组。默认监听 43897，默认心跳 5 Hz。

**学生操作**

1. 趴下状态清场，核对 IP 与状态端口。
2. 运行上述命令并等待结束。
3. 记录 10 s 内发送、状态、关节帧数量，以及最终状态、电量和前向速度。
4. 如果无关节帧，仍可继续只读状态学习，但 task03 的四膝辅助判据会受影响。

**验收标准**

- 无 ICMP 端口不可达。
- `rx_count > 0`，终端报告双向链路通过。
- 学生能解释“状态帧持续增长”和“仅发送计数增长”的差别。
- 关节帧为 0 时，记录为告警而不是隐瞒。

**常见错误**

- 使用 `--state-port 0` 后期待双向确认：该模式只统计发送。
- 将最后一次显示的状态当作实时状态：应同时记录帧龄或持续计数。
- 在状态不通时继续起立：先修复链路。

### task02：状态帧与关节帧只读观测

**目标**：读取 `0x0901/0x0902`，将字段与状态机动作对应。

**教师演示要点**

```bash
python3 task02_state_receiver.py --duration 10 --joints --interval 1
```

本任务会发送 5 Hz 心跳，但不发送任何运动命令，机器人保持当前姿态。

**学生操作**

1. 运行命令，记录至少 3 组不同时间的三元组。
2. 找到四个带 `*` 的膝关节，核对其索引为 2、5、8、11。
3. 记录前/后超声波、前后速度、侧向速度、偏航角速度和四膝均值。
4. 根据最终状态说明下一步：趴下可准备起立；稳定站立可进入 task03；过渡态应等待。
5. Ctrl-C 退出，确认机器人没有运动。

**验收标准**

- 状态帧与关节帧均持续接收，能正确换算 rad/deg。
- 三元组解释正确，尤其不会把 98 当作故障或站立完成。
- 记录中包含至少一个超声波值和四膝均值。
- 明确说明本任务“只读运动状态”，但仍有心跳发送。

**常见错误**

- 关节值为 `?` 仍继续 task03：task03 需要 `0x0902`，先排查。
- 将超声波两值理解为左右距离：它们是前/后距离。
- 反复按键或发送姿态命令来“刷新观测”：只读任务不需要运动指令。

### task03：起立、力控站立、趴下与归零

**目标**：理解 `趴下 → 起立过渡 → 稳定站立 → 保持 → 趴下 → 回零 → 趴下` 状态链。

**教师演示要点**

```bash
python3 task03_stand_to_force.py --hold 10
```

首次演示保持默认 10 s。`--hold 0` 表示一直保持，直到 Ctrl-C；不要在课堂中超时无人看管。

**学生操作**

1. 悬挂或护架扶稳，确认状态/关节帧就绪。若已在 `(6,0,0)` 且四膝 60°～90°，脚本会跳过起立。
2. 运行命令，观察阶段 A。起立期间只应有心跳，无轴指令。
3. 起立成功必须同时看到 `(6,0,0)` 和四膝均值 60°～90°连续 3 s。若启动时已经满足单次稳定判据，脚本会直接跳过起立，不重新执行 3 s 等待；应在阶段 B 的保持日志中补足连续稳定证据。
4. 阶段 B 每秒观察状态与四膝；记录保持期间是否出现 `⚠`。
5. 阶段 C 先稳定趴下，再发 `0x21010C05`；记录是否观察到 `(17,0,0)`，是否随后回到 `(1,0,0)`。
6. 收尾后人工确认机器人稳定趴下、腿部无线缆缠绕，再解除扶稳。

**验收标准**

- 终端明确报告起立成功，而不是只发送了 `0x21010202`。
- 保持结束仍在稳定站立判据内，或能说明干扰来源。
- 默认流程观察到 `(17,0,0)` 后回到 `(1,0,0)`。
- 归零前后四膝读数只作为编码器置零后的记录，不要求两者相同。
- `--no-home` 实验必须明确标注“未收尾归零”，不能记为完整归零成功。

**常见错误**

- 在非趴下、非稳定站立状态强行使用 `--force`：可能发出不符合当前状态机预期的切换命令，必须由教师决定。
- 将“四膝大于 130°”当作归零完成：必须看到 17 再回到 1。
- 连续按 Ctrl-C：首次中断进入收尾，再次中断可能使机器人停在中间态，应立即人工扶稳并报告。
- 看到 `(7,0,0)` 还重复发趴下命令：应等待自然稳定，公共 `ensure_sit()` 已考虑过渡态。
- 把 `--no-home` 理解为启动前也不归零：该参数只控制收尾；当前主流程没有独立启动前归零。

### task05：移动模式与低速步态

**目标**：在**不前进**的前提下完成移动模式与低速步态准备。

**教师演示要点**

```bash
python3 task05_move_mode_low_gait.py --hold 10 --hold-hz 30
```

`--hold-hz` 低于 20 会被拒绝。阶段 B 先发移动模式，再启动三轴零值流，最后发低速步态。

**学生操作**

1. 从稳定趴下开始，确认场地和扶稳条件。
2. 运行命令，记录起立成功和切步态成功两条日志。
3. 核对整个保持阶段 `forward=0`，机器人不应发生前进位移。
4. 记录移动就绪时的状态三元组和四膝均值，允许 `(6,0,0)` 或 `(6,0,1)`。
5. 收尾观察 forward 归零、轴流停止、趴下与归零。
6. 若阶段 B 失败，记录当前 gait，不绕过检查进入 task06。

**验收标准**

- `gait_state=0`，四膝均值在 60°～130°。
- 保持阶段三轴中的 forward 始终为零，无点动或位移指令。
- 轴流频率达到或超过 20 Hz；课堂默认使用 30 Hz。
- 默认收尾完成趴下与归零确认。
- 能解释 77.5° 附近的站立与 121.4° 附近的半蹲就绪都可能在代码允许范围内，而不把某个实测值当作通用硬件参数。

**常见错误**

- 在 AI 状态 `basic=16` 期待普通步态切换生效：先恢复非 AI 状态。
- 认为 `gait=0` 单独就代表可移动：还需 `basic=6`、四膝范围和有效遥测。
- 把 task05 当作移动实验：它只做准备，forward 一直为零。
- 保持阶段无人看管：脚本可能正在保持半蹲或等待收尾。

### task06：前进点动与死区验证

**目标**：用短脉冲验证前向轴方向、前向死区和零值停车。

**教师演示要点**

```bash
python3 task06_axis_tap.py --value 7000 --duration 0.8 --cooldown 2
```

参数检查要求 `value > 6553`、`hold_hz >= 20`；`duration > 2` 仅给出偏长警告。第一次真机点动应保留默认短时长。

**学生操作**

1. 确认前方至少 1 m 无障碍，机器人由安全员扶稳或护架限制。
2. 运行默认参数一次，记录点动前基线、点动期速度峰值/均值、停车后速度峰值。
3. 确认点动期 `vel_body[0] > 0.02 m/s`，即机器人向前。
4. 确认 forward 已回零且停车后速度低于 `0.02 m/s`；若停车样本缺失或出现异常负速度，不能据代码返回值直接判通过。
5. 观察收尾是否稳定趴下并归零。
6. 如需第二次，只改变一个参数，例如将 `duration` 从 0.8 增至 1.0；不要同时增大轴值和时长。
7. 比较 `pos_world[0]` 的变化，但注明它是 IMU 积分参考，不是卷尺测量。

**验收标准**

- 点动期前向速度峰值大于 `0.02 m/s`，方向为正。
- 停车观察有有效状态样本，速度绝对值在教师规定观察窗口内低于 `0.02 m/s`。
- 日志明确报告“方向正确 + 已停稳”；仅“~方向正确”不算完整通过。
- 收尾完成趴下与归零，或明确记录 `--no-home` 的未归零状态。
- 能解释 `value <= 6553` 被拒绝是死区保护，而不是网络故障。

**常见错误**

- 一开始就使用大轴值或长 duration：先完成默认点动，场地和停车能力未验证前不加码。
- 只检查“进程正常结束”：task06 的部分成功也可能正常结束。
- 停车样本为 `None` 仍记成功：应重新取得有效停车遥测。
- 将 task06 的有符号停车峰值当作绝对速度：人工核对日志和实际运动。
- 点动后立即停止轴流：应保持零轴流减速。
- 用很大的世界位移差代替速度判据：位置可能漂移，仅作参考。

## 思考题

1. task01 的 tx/rx/joint 三类计数分别证明什么？
2. task02 不发运动命令但发心跳，是否仍可能影响机器人？为什么课堂仍将其归为只读任务？
3. 为什么 task03 要求 `(6,0,0)` 和四膝角度同时满足，而 task05 接受更宽的 60°～130°？
4. task05 的三轴零值流与 task03 的“只发心跳”有何目的差异？
5. task06 的方向判据和停车判据为什么必须分开记录？
6. 为什么 `vel_after_peak=None` 或返回 True 都不能替代教师对停车日志的检查？
7. 归零前后四膝读数为何可能不同？真正的归零成功证据是什么？
8. 如果每次都在 task05 阶段 B 失败，应检查哪些状态和端口，而不是直接增大轴值？

## 验收标准

| 任务 | 必需证据 | 通过条件 |
|---|---|---|
| task01 | 终端统计与结论 | 有状态帧、无 ICMP 不可达，双向链路通过 |
| task02 | 三元组、关节/四膝、超声波记录 | 状态与关节解析正常，字段解释正确 |
| task03 | 起立、保持、趴下、17→1 日志 | 起立判据连续 3 s 满足，归零状态序列完整 |
| task05 | gait、四膝、零 forward、收尾日志 | 移动准备就绪且全程不前进，收尾安全 |
| task06 | 点动速度、停车速度、收尾日志 | 方向正确，有有效停车样本且停稳，收尾完成 |

单元总评还需考察：规范使用命令行、如实记录异常、按口令停车、退出后确认姿态。任一安全项缺失，不因技术指标合格而自动通过。

## 常见错误汇总

| 错误/现象 | 判断线索 | 正确处理 |
|---|---|---|
| 有发送无接收 | tx 增长、rx=0 | 检查上报目标、43897 占用和防火墙 |
| 98 后直接判故障 | 三元组首项为 98 | 按初始待机处理，电量高于 20% 才首次起立 |
| task03 等待超时 | 无四膝、非 `(6,0,0)`、外力阻挡 | 先查链路与姿态，不盲目重发或加轴 |
| task05 切步态失败 | basic=16 或 gait 非 0 | 确认非 AI 移动模式，重新按流程准备 |
| task06 未动 | 峰值不大于 0.02、轴值在死区、未就绪 | 核对模式、死区、状态和场地 |
| task06 方向为负 | 点动期速度显著为负 | 停止实验，检查其他控制源与方向约定 |
| task06 未停稳 | 停车日志仍有较大速度 | 增大观察时间、保持零轴流、排查指令残留 |
| 归零未确认 | 未见 17 或 17 后未回 1 | 记为失败，检查发送前状态和其他 UDP 客户端 |
| 收尾后仍站立 | Ctrl-C 被打断或流程提前返回 | 人工扶稳，按教师指导完成趴下/归零 |
