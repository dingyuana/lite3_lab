# Lite3 大学生真机控制课程导学

## 学习目标

完成本课程后，学生应能够：

1. 说明 Lite3 真机项目中的 UDP 命令、状态帧、关节帧、心跳、轴流和状态机之间的关系。
2. 在教师指导下完成链路检查、只读观测、起立/趴下/归零、低速移动和多轴方向验证。
3. 根据状态三元组和遥测数据判断动作是否完成，不把“命令已发送”误认为“机器人已执行”。
4. 使用 task10 图形界面完成手动控制，并理解姿态门控、前后超声波防撞与侧移风险。
5. 完成 task12 的人体检测、单应标定、离线验证、PID 跟随和安全停车实验。
6. 识别帧龄、感知超时、看门狗、死区和 dummy 标定拦截等安全机制，形成可复现的排障记录。

总建议学时为 **16 学时**，每次 2 学时；可按设备数量与先修水平调整。

## 先修知识

- Python 基础：函数、参数、异常、线程概念，以及命令行运行脚本。
- 计算机网络基础：IP 地址、端口、UDP 无连接通信；知道 UDP 发送成功不等于对端已执行。
- 数学基础：二维坐标、角度、速度、比例—积分—微分（PID）与误差反馈。
- 图像基础：像素坐标、仿射/单应变换、目标检测框的基本概念。
- 实验纪律：能执行stop、清场、扶稳和异常上报，不擅自修改阈值或绕过安全门控。

不要求事先掌握机器人运动学或 YOLO 训练；本课程重点是端到端控制和安全验证。

## 核心概念

### 项目地图与历史编号

所有真机脚本位于同一目录，公共协议实现为 `lite3_common.py`。教学运行顺序如下：

| 任务 | 入口 | 教学定位 |
|---|---|---|
| task01 | `task01_heartbeat.py` | 心跳与双向链路统计 |
| task02 | `task02_state_receiver.py` | 只读状态与关节观测 |
| task03 | `task03_stand_to_force.py` | 起立、稳定站立、趴下、归零 |
| task05 | `task05_move_mode_low_gait.py` | 移动模式与低速步态准备，不前进 |
| task06 | `task06_axis_tap.py` | 短时前进点动、死区和停车观察 |
| task07 | `task07_axis_stream_forward.py` | 持续前进与停车确认 |
| task08 | `task08_ultrasonic_guard_forward.py` | 前后超声波保护前进 |
| task09 | `task09_axis_directions.py` | 前进、后退、左移、右移符号验证 |
| task10 | `task10_gui.py` | 键盘、视频、状态与控制面板 |
| task12 | `task12_follow.py` | 标定与人体视觉跟随 |

**task04 在历史版本中缺失，不是学生漏做，不需要补写或补跑。task11 已并入 task12**；`legacy/task11_follow.py` 仅用于阅读历史实现，不得作为安装、测试或课堂运行入口。

### 两个教学端口与两条数据路径

- 控制器向机器人默认 `192.168.1.120:43893` 发送 UDP 命令。
- 状态接收端默认在本机 UDP `43897` 监听。实际机器人上报目标必须由实验教师预先配置并验证；代码绑定端口本身不能证明上报路由正确。
- 指令路径与上报路径共同构成闭环。只有“发送计数增长”只能证明本机尝试发送；同时收到有效 `0x0901` 状态帧，才可确认双向链路可用。

### 状态不是单字节

公共模块用三元组 `(basic, gait, motion)` 描述机器人状态。重点掌握：

- `(98,0,0)`：运控程序启动后的初始待机，尚未触发首次起立；不是故障，也不是站立或回零成功。
- `(1,0,0)`：趴下。
- `(4,0,0)`、`(5,0,0)`：准备起立、正在起立。
- `(6,0,0)`：力控站立、平地低速、静止。
- `(6,0,1)`：力控站立、平地低速、踏步/扭动，属于移动就绪姿态。
- `(7,0,0)`：正在趴下。
- `(17,0,0)`：回零。
- `(8,0,0)`：失控保护。

### 数据新鲜度与动作确认

- `get_state()` 和 `get_joint()` 默认只返回帧龄小于 0.5 s 的数据；过期返回 `None`。
- task03 发起立后的成功判据为 `(6,0,0)` 且四膝均值处于 60°～90°，连续 3 s；若启动时已满足单次稳定判据，脚本会跳过起立，此时应通过保持阶段补足连续稳定证据。
- task05/06/07/08/09 的移动准备要求 `basic=6`、`gait=0` 且四膝均值处于 60°～130°；此时 `motion=0` 或 `motion=1` 都可能有效。
- 趴下辅助判据为四膝均值大于 130°；公共 `ensure_sit()` 还要求状态稳定在 `(1,0,0)`。
- 公共 `ensure_home()` 要求先稳定趴下，再观察 `(17,0,0)`，随后回到 `(1,0,0)`；未见 17 或未返回趴下都不算成功。

### 零值轴流与死区

移动模式就绪后，脚本通常以 30 Hz 持续发送前向、侧向、偏航三个轴值。前进、侧向、偏航的代码死区分别为 **6553、12553、9553**。正值必须大于对应死区，负值必须小于对应死区的相反数，零值始终保持零。

停车时先发全轴零值并维持轴流，让机器人减速，而不是立即关闭 UDP。代码注释指出轴指令超时可能使底层接管；课堂实验应始终保留停车观察时间。

## 教师演示步骤

1. 展示项目目录，指出 `README.md`、`lite3_common.py`、`assets/`、`tests/`、`legacy/` 和各任务入口。说明本次只按现有代码教学，不现场修改代码。
2. 在 WSL 中进入项目目录，确认默认 IP、状态端口和 RTSP 地址符合本实验室配置。若不同，记录实际参数，并在命令中显式传入。
3. 演示环境检查与依赖安装；不要在机器人已起立时才开始排查依赖。
4. 展示软急停命令和人工扶稳位置，强调软急停不是物理断电，也不能替代机械防护。
5. 运行 `python3 task01_heartbeat.py --duration 5`，解释发送、状态、关节帧三类计数，以及 ICMP 端口不可达的含义。
6. 运行 `python3 task02_state_receiver.py --duration 5 --joints`，指出状态三元组、关节角度、前后超声波和身体速度。
7. 在悬挂或护架条件下演示 task03 的完整状态转换，让学生口述每一步成功证据。
8. 展示 task12 的离线入口：`python3 task12_follow.py --selfcheck` 和 `python3 task12_follow.py --offline --dummy-h`，明确它们不会发送运动指令。
9. 按[02-协议与安全.md](02-协议与安全.md)完成安全交底，再分组进入真机实操。

## 学生实操步骤

### 实验前检查

1. 三人复述操作员、安全员和记录员职责，确认所有人知道停止口令。
2. 清理机器人前后至少 2 m 范围，并额外确认侧面空间；侧移没有超声波保护。
3. 检查悬挂、护架或人工扶稳条件，检查线缆未缠绕腿部。
4. 确认机器人电量满足实验要求；初始待机 98 下首次起立要求电量高于 20%。
5. 关闭其他可能向同一机器人发送运动命令的客户端，避免多个控制源竞争。
6. 在 WSL 项目根目录运行以下命令：

```bash
cd ~/lite3_lab/real_robot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
sudo apt install python3-tk
```

若环境已由教师预装，不要重复覆盖；先执行 `python3 --version`、`python3 -c "import cv2, numpy, PIL"` 检查。

### 课堂记录模板

每次真机运行记录以下字段，可直接写入实验报告：

- 日期、组号、任务名、机器人 IP、本地状态端口、命令及参数。
- 运行前状态三元组、电量、四膝均值、前后距离。
- 关键日志时间点、动作期速度峰值、停车后速度、是否观察到目标状态。
- 异常时的界面提示或终端原文，不凭记忆改写。
- 是否按 T/Esc/停止按钮/Ctrl-C 退出，退出后机器人姿态与运动轴是否归零。
- 教师安全检查签字。

### Windows 访问说明

Windows 可在资源管理器打开：

```text
\\wsl.localhost\<发行版>\home\<用户>\lite3_lab\real_robot
```

但 **Python 命令应在 WSL 的项目目录中运行**。不要把 Windows 版 Python 的 `.venv` 与 WSL 混用；RTSP、UDP 上报和相机显示也应在同一套已验证的环境中调试。

## 思考题

1. 为什么 task01 的“发送心跳”计数增长，仍不足以证明机器人已经执行了运动指令？
2. `(98,0,0)`、`(6,0,0)`、`(6,0,1)`、`(17,0,0)` 各自能说明什么，不能说明什么？
3. 为什么起立阶段只发心跳，而移动阶段需要持续发送三轴零值？
4. 为什么“看到四膝角度大于 130°”仍不能替代公共归零函数的状态序列确认？
5. 为什么侧移实验必须人工清场，不能依赖前后超声波？
6. task04 与 task11 应如何处理，为什么不应把历史脚本作为现行入口？

## 常见错误

| 错误做法 | 后果 | 正确做法 |
|---|---|---|
| 在 Windows 中直接双击脚本或混用虚拟环境 | 导入失败、显示或网络环境不一致 | 在 WSL 项目根目录激活 `.venv` 后运行 |
| 未确认上报目标就运行只读实验 | 有发送计数但无状态帧 | 先完成 task01 双向链路检查 |
| 把 98 当作连接故障或回零成功 | 对状态机作出错误判断 | 按“初始待机”解释，并等待实际起立状态 |
| 起立时同时发送轴指令 | 站立过程被改变，可能进入移动就绪半蹲 | 起立与保持阶段只发心跳 |
| 多个 GUI 或脚本同时控制 | 指令互相覆盖，停车与状态确认失效 | 一台机器人同一时刻只保留一个控制客户端 |
| 先做持续前进再练停车 | 缺少停车能力就暴露在移动风险中 | 先通过 task06 点动和停车观察 |
| 运行 `legacy/task11_follow.py` | 使用已退出教学与测试链路的历史实现 | 只运行 `task12_follow.py` |
| 把旧注释当作当前验收逻辑 | 对程序结果产生误判 | 以代码、终端日志和本讲义“实现说明”为准 |
