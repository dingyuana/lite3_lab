课程地图

课程定位

本课程面向机器人工程、自动化、计算机等专业本科实训，围绕四足机器人的通信、状态机、运动控制、视觉跟踪、物理仿真、强化学习部署和 ROS2 接口展开。课程强调可复现实验、安全边界和工程证据，不以“演示成功一次”作为唯一目标。

培养目标

完成课程后，学生能够：

  1. 描述四足机器人感知—决策—执行—反馈闭环。
  2. 使用 UDP 协议读取状态并发送安全运动命令。
  3. 根据姿态、步态和速度状态设计顺序控制流程。
  4. 理解死区、帧龄、超时、看门狗和急停等实时安全概念。
  5. 使用 PyBullet/MuJoCo 建立可重复实验。
  6. 解释 RL 观测、动作缩放和 PD 力矩伺服。
  7. 使用 ROS2 话题传递关节指令并识别数据前端与算法边界。
  8. 记录实验、分析故障并提交可评价的证据。

模块关系

公共基础
  ├── 真机 task：协议 → 状态机 → 轴控制 → GUI → 视觉跟随
  └── 仿真 stage：物理引擎 → RL 部署 → ROS2 → LiDAR 数据前端

联合课程中，公共基础提供统一坐标系、单位、安全和记录规范；真机与仿真分别验证硬件约束和算法正确性。

学时方案

公共基础 10、真机 22、仿真 22、综合对比 6、考核 4。综合项目要求同一速度指令分别在仿真和真机执行，比较速度、姿态、延迟和失败条件。

先修与分组

建议先修 Python、线性代数和计算机网络基础。每组 3~4 人，角色轮换：安全员、操作员、记录员、分析员。真机操作员和安全员不能由同一人长期担任。

教学资源

  • shared/：公共基础课程。
  • real_robot/：真机代码、资源和回归测试。
  • simulation/：仿真代码、模型定位和测试。
  • docs/：本课程地图、教师指南和量规。
  • HTML 课程页：支持离线阅读、章节直达和打印全展开。

验收原则

过程评价与结果评价并重。出现安全违规时，实操项目按安全门槛直接判定不合格；技术故障则根据记录、诊断和恢复过程给分。

01

教师授课指南

课前准备

  1. 冻结课程版本，记录 Git 提交和依赖版本。
  2. 真机课程检查电量、网络、悬挂装置、急停命令和状态监听。
  3. 仿真课程检查模型、ONNX 策略、显示环境和 ROS2 工作空间。
  4. 预跑所有演示命令，保存预期输出和异常样例。
  5. 按安全考核结果分组，明确安全员拥有一票否决权。

课堂组织

每次 2 学时建议采用以下节奏：

环节时间教师任务
目标与安全10 min明确验收条件和高风险操作
概念讲解25 min结合代码说明核心机制
教师演示20 min展示正常路径和一个失败路径
学生实操45 min巡视、记录共性错误
复盘与提交10 min收日志、提问、布置报告

演示策略

先只读，再运动

真机从 task01/task02 开始，先确认链路和状态，再允许发送起立或运动命令。不要用 GUI 按钮代替协议基础教学。

正常路径与失败路径成对演示

  • task07：正常前进与未停稳。
  • task12：新鲜帧与过期帧。
  • stage3：正确重力投影与符号错误。
  • stage5：明确真值里程计不是 SLAM 估计。

让学生预测结果

在修改参数前先写预测，例如“减小 cooldown 会导致停车时间不足”。预测错误本身是诊断材料，不应简单扣分。

分层任务

  • 基础层：按步骤运行脚本，完成状态和日志记录。
  • 进阶层：修改一个参数，设计对照实验并解释结果。
  • 挑战层：构造异常输入，验证拒绝逻辑或安全降级。

真机课堂特殊要求

  • 同一时刻只允许一个控制端。
  • 起立、转向、首次跟踪必须使用防跌倒措施。
  • 任何安全员喊停，操作员立即执行停车/急停。
  • 不让学生在未确认四膝和速度时进入下一阶段。
  • 归零必须由教师确认姿态后操作。

仿真课堂特殊要求

  • 先运行 NumPy 单元测试，再打开图形仿真器。
  • RL 实验先检查 45 维观测和 PD 力矩，再讨论步态效果。
  • ROS2 实验先验证消息数量和有限值，再连接控制器。
  • stage5 必须区分 /ground_truth_odom 与 SLAM 估计输出。

常见课堂误区

  1. 把状态码当作全部验收条件。
  2. 把读取数据的时间当作数据产生时间。
  3. 把目标关节角直接作为电机力矩。
  4. 把 dummy Homography 用于真机。
  5. 把仿真真值里程计称为 SLAM。
  6. 同时修改多个参数，导致无法归因。

课后复盘

每组提交一页实验记录：目标、命令、关键观测、异常、根因假设、验证证据、收尾状态。教师按周汇总共性问题，更新下一轮演示案例。

02

考核评价量规

考核结构

项目权重说明
安全与规范20%安全考核、实验纪律、收尾
过程性实验30%日志、预测、对照、课堂参与
综合实操25%真机或仿真综合任务
报告与答辩25%证据、分析、表达、反思

安全门槛优先于分数：出现未授权运动、无视急停、真机使用 dummy 标定等行为，对应实操直接不合格，并按实验室制度处理。

综合实操评分

维度分值优秀标准
方案设计10状态序列完整，验收指标可测量
正确性20协议、单位、坐标、观测和控制律正确
安全性20异常分支完整，停车与收尾可靠
调试能力15单变量对照，证据支持根因
记录与表达10命令、参数、日志、结论完整可复现
创新与反思5能提出有依据的改进并说明局限

报告评分细则

  • 问题定义 10 分：目标、输入、输出、约束清楚。
  • 方法 20 分：公式、参数、状态机或流程图准确。
  • 实验证据 25 分：包含原始日志、曲线/截图和异常样例。
  • 分析 25 分：区分事实与假设，对照实验充分。
  • 安全与复现 10 分：收尾完整，他人可照文档复现。
  • 表达 10 分：结构清楚，图表规范，结论不过度外推。

真机任务验收示例

task07 持续前进必须同时满足：

  1. 起立和步态阶段通过。
  2. 前进期速度峰值大于 0.02 m/s。
  3. 前进方向符合预期。
  4. --cooldown 窗口内停稳。
  5. 收尾完成趴下，按任务要求归零。
  6. 日志包含参数、速度、位置和收尾状态。

仅“机器人移动过”不能获得正确性满分。

仿真任务验收示例

stage3 必须同时满足：

  1. 重力投影函数通过水平姿态测试。
  2. 默认关节向量为 (0,-0.65,1.3) 循环。
  3. 观测为 45 维且顺序正确。
  4. PD 输出为力矩并按控制范围限幅。
  5. 能解释仿真步态与真实硬件差异。

评分校准

开课前由两名教师对同一份样例独立评分，差异超过 5 分的维度需讨论校准。课程中每周抽取一份报告进行盲评，避免不同小组标准漂移。

反馈语言

反馈应指出“证据—问题—下一步”。例如：“速度峰值为 0.003，未越过方向阈值；下一步先检查移动模式与步态，再检查轴死区。”

03

实验室管理与复盘

设备与角色

每组设置安全员、操作员、记录员、分析员，轮换执行。安全员负责空间检查、悬挂确认、急停准备和停止指令；操作员只负责发送命令；记录员保存日志；分析员负责对照实验和报告。

真机控制端应显示唯一会话编号，避免多个 GUI 同时发送 UDP 命令。实验结束后由安全员确认轴流停止、机器人姿态和 UDP 关闭。

版本管理

每轮课程冻结一个发布版本：

  • 记录主仓库提交。
  • 记录 Lite3_rl_deploy 与 sdk_deploy 子仓库提交。
  • 导出 Python 依赖版本。
  • 保存 real_robot/assets/H.npy 的标定日期和设备对应关系。
  • 不把不同机器人的标定文件混用。

实验预约与检查

预约单包含课程模块、设备、场地、时间和负责人。开课前 10 分钟完成检查表：

  • 网络与状态端口。
  • 电量与悬挂。
  • 地面与线缆。
  • 软急停命令。
  • 日志保存位置。
  • 实验后的归零/趴下负责人。

异常与事故

出现跌倒、碰撞、异常抽搐、冒烟或线缆缠绕时：

  1. 安全员喊停并执行软急停或 hardware 急停。
  2. 不立即重新起立，先切断运动来源。
  3. 保护现场，记录时间、命令、状态和日志。
  4. 教师检查设备并决定是否恢复。
  5. 未确认安全前不得删除日志或重置固件零位。

事故复盘聚焦系统和流程，不归咎个人。重点检查权限、培训、检查表、状态反馈和急停可达性。

课程复盘

每轮课程结束后统计：

  • 各任务首次通过率。
  • 常见故障类别与分布。
  • 安全考核未通过项目。
  • 真机与仿真联合实验的差异。
  • 学生报告中的概念误区。
  • 文档与代码不一致之处。

根据统计更新讲义、测试和演示案例。代码修复应同时补充回归测试，防止同类问题再次进入课堂。

资产维护

  • H_dummy.npy 与真实 H.npy 分目录标识，dummy 不得作为真机默认资源。
  • YOLO 权重记录来源和版本，不随意替换。
  • 仿真模型与策略路径由 project_paths.py 管理。
  • 历史 task11 仅作阅读，不安排为学生运行入口。

期末材料归档

归档课程版本、分组表、安全考核、实验日志、报告、评分表、复盘纪要和改进清单。学生数据按学校规定脱敏，不公开机器人网络配置和无关个人信息。
