Lite3 大学生真机控制课程导学

学习目标

完成本课程后，学生应能够：

  1. 说明 Lite3 真机项目中的 UDP 命令、状态帧、关节帧、心跳、轴流和状态机之间的关系。
  2. 在教师指导下完成链路检查、只读观测、起立/趴下/归零、低速移动和多轴方向验证。
  3. 根据状态三元组和遥测数据判断动作是否完成，不把“命令已发送”误认为“机器人已执行”。
  4. 使用 task10 图形界面完成手动控制，并理解姿态门控、前后超声波防撞与侧移风险。
  5. 完成 task12 的人体检测、单应标定、离线验证、PID 跟随和安全停车实验。
  6. 识别帧龄、感知超时、看门狗、死区和 dummy 标定拦截等安全机制，形成可复现的排障记录。

先修知识

  • Python 基础：函数、参数、异常、线程概念，以及命令行运行脚本。
  • 计算机网络基础：IP 地址、端口、UDP 无连接通信；知道 UDP 发送成功不等于对端已执行。
  • 数学基础：二维坐标、角度、速度、比例—积分—微分（PID）与误差反馈。
  • 图像基础：像素坐标、仿射/单应变换、目标检测框的基本概念。
  • 实验纪律：能执行stop、清场、扶稳和异常上报，不擅自修改阈值或绕过安全门控。

不要求事先掌握机器人运动学或 YOLO 训练；本课程重点是端到端控制和安全验证。

两个教学端口与两条数据路径

  • 控制器向机器人默认 192.168.1.120:43893 发送 UDP 命令。
  • 状态接收端默认在本机 UDP 43897 监听。实际机器人上报目标必须由实验教师预先配置并验证；代码绑定端口本身不能证明上报路由正确。
  • 指令路径与上报路径共同构成闭环。只有“发送计数增长”只能证明本机尝试发送；同时收到有效 0x0901 状态帧，才可确认双向链路可用。

状态不是单字节

公共模块用三元组 (basic, gait, motion) 描述机器人状态。重点掌握：

  • (98,0,0)：运控程序启动后的初始待机，尚未触发首次起立；不是故障，也不是站立或回零成功。
  • (1,0,0)：趴下。
  • (4,0,0)、(5,0,0)：准备起立、正在起立。
  • (6,0,0)：力控站立、平地低速、静止。
  • (6,0,1)：力控站立、平地低速、踏步/扭动，属于移动就绪姿态。
  • (7,0,0)：正在趴下。
  • (17,0,0)：回零。
  • (8,0,0)：失控保护。

数据新鲜度与动作确认

  • get_state() 和 get_joint() 默认只返回帧龄小于 0.5 s 的数据；过期返回 None。
  • task03 发起立后的成功判据为 (6,0,0) 且四膝均值处于 60°～90°，连续 3 s；若启动时已满足单次稳定判据，脚本会跳过起立，此时应通过保持阶段补足连续稳定证据。
  • task05/06/07/08/09 的移动准备要求 basic=6、gait=0 且四膝均值处于 60°～130°；此时 motion=0 或 motion=1 都可能有效。
  • 趴下辅助判据为四膝均值大于 130°；公共 ensure_sit() 还要求状态稳定在 (1,0,0)。
  • 公共 ensure_home() 要求先稳定趴下，再观察 (17,0,0)，随后回到 (1,0,0)；未见 17 或未返回趴下都不算成功。

零值轴流与死区

移动模式就绪后，脚本通常以 30 Hz 持续发送前向、侧向、偏航三个轴值。前进、侧向、偏航的代码死区分别为 6553、12553、9553。正值必须大于对应死区，负值必须小于对应死区的相反数，零值始终保持零。

停车时先发全轴零值并维持轴流，让机器人减速，而不是立即关闭 UDP。代码注释指出轴指令超时可能使底层接管；课堂实验应始终保留停车观察时间。

核心概念

UDP 命令头

lite3_common.py 将 UDP 载荷开头定义为三个小端无符号 32 位整数：

字段含义
code命令码或上报帧码
第二个整数简单命令中的 value；复杂命令中的 payload 字节长度
type简单命令为 0；复杂命令默认为 1

pack_simple() 生成 12 字节载荷；pack_complex() 在 12 字节头后追加 payload。接收端只处理 type=1 的遥测帧；扬声器状态 0x11050F08 是 type=0 的特例。

UDP 本身没有应用层的“已执行”回执。send() 的发送计数增长只表示本机完成了一次 sendto() 调用；动作是否执行必须看后续状态与遥测。

状态帧与关节帧

  • 0x0901：RobotStateUpload 结构体，代码断言其 payload 为 208 字节。部分上报帧带 4 字节 98 前缀，总 payload 为 212 字节；解析时跳过前缀。两种格式都支持。
  • 0x0902：12 个关节角，double 类型，payload 为 96 字节。关节原始值为弧度，日志同时换算为度。
  • 四膝索引为 [2,5,8,11]，对应左前、右前、左后、右后膝关节。
  • 状态默认接收端口为 43897，控制目标默认端口为 43893。这些是项目默认值，不是对现场网络配置的证明。

状态结构中的超声波为前/后两个 double 值。任务读取的是机器人上报的米制距离；不能把某个读数当作侧向保护，也不能假设传感器永远返回有限正数。

三元组含义课堂判断
(98,0,0)初始待机尚未首次起立；不能作为站立或归零完成证据
(1,0,0)趴下归零/起立流程的起点之一
(4,0,0)准备起立过渡态，等待
(5,0,0)正在起立过渡态，只发心跳
(6,0,0)力控站立、低速、静止task03 的稳定站立状态
(6,0,1)力控站立、低速、踏步/扭动可作为移动就绪姿态

判据是组合条件：task03 稳定站立还要求四膝均值 60°～90°连续 3 s；移动就绪要求四膝均值 60°～130°；趴下辅助判据要求四膝均值大于 130°。这些阈值是项目代码中的实验判据，不是机器人额定硬件参数。

新鲜度、帧龄与“读取不会刷新数据”

get_state(max_age=0.5) 与 get_joint(max_age=0.5) 只返回最新一帧，且要求帧龄严格小于指定值；state_age() 返回最新状态帧的原始年龄。

因此：

  • 多次读取旧帧不会让数据变新。
  • get_state() 返回 None 可能表示从未收到，也可能表示已经超过 0.5 s。
  • task12 必须用 snapshot()["state_age"] 更新声纳时间戳，不能把 snapshot() 调用时刻当作声纳采样时刻。
  • 视觉帧使用 VideoStream.latest_with_timestamp() 返回的采集时间戳，不能用 GUI 每 50 ms 刷新一次的时刻冒充新帧。

轴流、死区与停车

移动准备完成后，脚本以默认 30 Hz 发送前向、侧向、偏航轴。轴值范围由公共映射限制在约 ±32767；死区常量为：

  • 前向：6553。
  • 侧向：12553。
  • 偏航：9553。

task06/07/08 会拒绝小于或等于前向死区的 --value。task12 的 twist_to_axis() 会将落在死区内的小非零输出抬到死区外一单位，使后退和转向能够越过固件死区；零输入仍映射为零。

正常停车顺序：

  1. 三个运动轴写入 (0,0,0)。
  2. 维持零值轴流，同时观察 vel_body[0] 等遥测。
  3. 确认速度低于实验阈值或进入收尾状态。
  4. 需要结束实验时，再趴下并按任务要求归零。

核心概念

基础流程的共同结构

task03/05/06 共享以下教学结构，但细节不同：

  1. 建立控制器，启动 5 Hz 心跳与状态/关节接收。
  2. 确认遥测就绪，判断当前是否已经稳定站立。
  3. 需要起立时发送 0x21010202，等待 (6,0,0) 且四膝均值 60°～90°连续 3 s。
  4. task05/06 再切 0x21010D06 移动模式，启动默认 30 Hz 的三轴零值流，发送 0x21010300 低速步态。
  5. 移动准备成功判据为 basic=6、gait=0、四膝均值 60°～130°。
  6. 执行本任务的观察或点动。
  7. 运动轴归零，维持轴流减速，再趴下；默认收尾调用 ensure_home()。

这些脚本每次都从自己的启动流程重新判断姿态，不会自动继承上一个脚本的移动模式。上一个脚本已归零并趴下，是下一次真机运行最稳妥的起点。

站立与移动就绪不是同一件事

  • task03 的“稳定站立”是 (6,0,0) 与四膝 60°～90°连续 3 s。
  • task05/06 的“移动就绪”接受 basic=6、gait=0、四膝 60°～130°；既可能是 (6,0,0)，也可能是 (6,0,1) 半蹲踏步态。
  • 起立阶段发送轴指令会改变姿态，可能进入移动就绪半蹲。因此不能一边等待 task03 的稳定站立判据，一边试探轴值。

task06 的两个独立判据

  • 方向：点动期间前向速度峰值大于 0.02 m/s。
  • 停车：停车观察期间前向速度峰值小于 0.02 m/s。

代码的返回逻辑需要特别注意：

  • 点动期间没有状态样本时，方向判据失败。
  • 停车期间没有状态样本时，vel_after_peak is None 也被代码当作停稳。
  • 停车判据使用有符号的 max(vel_samples)，不是绝对峰值；大幅负速度不能被这个条件排除。
  • 当方向正确但停车未停稳时，函数仍可能返回 True，终端结论为“~方向正确，但停车后未完全停稳”。

因此，学生验收不得只看进程退出码或“全流程成功”字样，必须查看方向、停车和归零三段日志。

  5. 解释 task10 的前后防撞、侧移风险、状态门控以及 Esc/失焦停车。

  • 能使用 Tkinter 图形界面，理解按住/松开按键与窗口焦点。

核心概念

持续前进与停车窗口

task07 默认 forward=9000、运动 3 s、停车观察 3 s，轴流默认 30 Hz。安全停车函数接收 --cooldown，在观察窗口内寻找 abs(vel_body[0]) < 0.02 m/s；只有方向和停车都确认才返回成功。

task07 启动门控与基础任务不同：

  • 当前为 (1,0,0) 或 98 时允许继续进入自身起立流程。
  • 当前为其他状态时，先调用 ensure_home()；必须确认归零并回到 (1,0,0) 才继续，否则停止任务。

这是“未知/移动中间状态不得直接起步”的保护，不应通过关闭状态监听绕过。

超声波保护不是自动导航

task08 在每个控制循环读取前/后声纳：

  • 前或后距离小于 1.0 m：forward 轴归零，保持原地运动。
  • 任一距离不是有限数：也按阻塞处理。
  • get_state() 返回 None：forward 轴归零，并提示状态未知。
  • 两侧均恢复到不小于 1.0 m：继续发送原 forward 轴值。
  • 避障/阻塞时间仍计入 duration，不会暂停计时延长总时长。

它不会绕行、不会侧移、不会倒车，也不会自动退出任务。这里的“原地运动”是继续发送零轴流并保持步态，不应理解为位置绝对不变。

task08 还有两个必须如实讲授的实现细节：

  1. --cooldown 参数虽然存在，但当前调用没有把它传给 _safe_stop()；安全停车函数内部硬编码观察上限 5.0 s。
  2. 当检测到过障且已停稳时，即使没有采集到正向速度样本，也可能返回避障成功；若方向正确但未停稳，当前代码仍可能返回 True。验收必须单独核对停车日志。

task10 的控制架构

  • task10_gui.py：Tkinter 界面、按键绑定、RTSP 显示、状态刷新。
  • task10_robot.py：UDP 控制、姿态状态机、30 Hz 三轴流、手动/跟踪互斥和前后防撞。

  • task10 界面中的“开始跟踪（T）”会加载 FollowSession，即使用户运行的是 task10 入口，跟踪功能仍来自 task12。

GUI 的状态刷新周期为 50 ms，但状态数据仍受公共 get_state() 的 0.5 s 新鲜度限制；界面看起来在刷新，不代表机器人数据也新鲜。

目标选择与脚点

TargetTracker 仅检测 classes=[0]（人体），默认置信度为 0.5：

  • 首次未锁定目标时，选择检测框水平中心最接近画面中心的人。
  • 锁定后按 YOLO track ID 持续寻找同一个人。
  • 跟踪点取检测框底边中点 (cx, y2)，不是框中心，也不是人体头部。
  • 检测框坐标非有限值时按无目标处理。
  • tracker 在无 ID 或锁定目标消失时增加丢失计数，超过 10 次清除锁定 ID；但跟随安全层只要当前无目标就立即停车。

地面标定与单应反投影

标定要求四个地面标记与相机画面中的四个点一一对应。代码使用 3×3 单应矩阵 H：

[u, v, 1]^T → H × [u, v, 1]^T → 除以第三项 → [X, Y, 1]

默认地面坐标为：

顺序标记地面坐标
1近左(-1, 1)
2近右(1, 1)
3远右(1, 3)
4远左(-1, 3)

原点位于机器人地面投影，X 向右、Y 向前，单位由代码定义为米。教师必须用卷尺按这套坐标实际布点，不能把图中“看起来相近”的位置直接写成 1 m/3 m。

代码要求源点和目标点都是顺序一致的凸四边形，允许整体顺时针或整体逆时针，拒绝交叉、自交或退化点序。求解后计算四个点的重投影残差，最大残差大于 0.005 m 时拒绝保存。

地面投影模型以“脚点位于同一平面”为前提。检测框底边如果落在台阶、椅子或遮挡物上，反投影距离可能明显错误；课堂应选择平整地面、完整人体和稳定光照。

双环 PID 与坐标误差

对目标脚点反投影得到 (lateral, forward) 后：

  • 前向距离 distance = forward；forward <= 0 或坐标非有限时立即停车。
  • 偏航误差 error_x = atan2(lateral, forward)，单位为弧度；目标在右时误差为正。
  • 偏航环使用滤波后的误差、比例项和微分项。
  • 距离环使用 distance - target_distance 的比例项与积分项。

DualLoopPID 的默认参数如下：

距离积分只在距离误差绝对值大于或等于 0.10 m 时更新；死区内输出速度为零，但已有积分不会自动清零。调用 update(..., active=False)、重置或停车时会同时清零滤波、积分和历史输出。

首次更新使用 dt=0.05 s，之后按单调时钟计算，dt 限制在 0.01～0.5 s。偏航微分使用滤波后误差的变化率；滤波系数随 dt 改变。速度与角速度还有输出斜率限制，避免误差突变时立即给出大幅轴值。

从 twist 到轴值

默认缩放：

  • 前向：vx × 40000。
  • 偏航：wz × 65534。
  • 侧向：跟随始终为 0。

_axis_value() 将结果四舍五入并限制在 ±32767。若结果是非零但落在死区内，会改为死区外一单位：

  • 前向最小非零绝对轴值为 6554。
  • 偏航最小非零绝对轴值为 9554。
  • 零输入始终输出零。

这一步保证低速后退和转向能越过固件死区，但不能证明方向正确。pid_selfcheck() 最后明确提示：偏航符号需悬挂测试真机确认。

视觉帧龄与独立看门狗

视频线程每次成功 capture.read() 后记录 time.monotonic()。跟随循环通过 latest_with_timestamp() 取回帧及其采集时间：

  • 无帧或时间戳不大于 0：安全停车。
  • 帧龄为负或大于 0.2 s：安全停车。
  • 每轮循环开始刷新 _last_update；独立线程每 0.05 s 检查一次。
  • 最近一次控制循环更新超过 1.0 s：轴归零、调用 stop_tracking() 退出跟踪状态（恢复手动可用）、结束会话。

帧龄解决“反复读取同一旧帧”的问题；看门狗解决“整个控制循环或推理卡住”的问题。两者不能互相替代。

SafetySupervisor.link_timeout=0.5 还检查最近一次成功 tracker.update() 的距离；超过 0.5 s 返回感知链路超时。目标为空但 tracker 正常返回时，该计时仍会刷新，随后由目标丢失规则立即停车。

声纳帧龄与距离迟滞

task12 从 robot.snapshot() 同时取得前声纳和 state_age，再调用：

update_ultrasonic(distance, age)
us_stamp = 当前单调时间 - age

因此声纳时间始终对原始状态帧负责，不会因为读取 snapshot 而变新。

真机跟随要求：

  • 状态原始帧龄不大于 0.3 s。
  • 前声纳存在、有限且大于 0。
  • 前声纳小于 1.0 m 时进入阻塞，大于 1.3 m 时解除。
  • 阻塞时决策为 STOP，不是仅禁止前进。

视觉目标距离使用另一组迟滞：

  • 小于 1.0 m：进入“过近”；大于 1.3 m：解除。
  • 大于 3.5 m：进入“过远”；小于 3.0 m：解除。
  • 过近：ONLY_TURN，前进轴为 0，只允许偏航。
  • 过远：STOP。
  • 1.0～3.5 m 之间且未处于迟滞状态：正常双环控制。

迟滞可减少阈值附近的频繁切换。task10 控制器还有第二层保护：跟踪前进受前声纳 1.0 m 阈值约束，跟踪后退受后声纳约束；一旦触发，forward 与 yaw 都归零，比 ONLY_TURN 更保守。

dummy 三重拦截

真机不得使用占位矩阵。当前实现从三个层次拦截：

  1. 命令行：--dummy-h 不同时带 --offline 时直接报错。
  2. FollowSession.start() 再次检查 dummy 标志与真机模式，防止绕过入口直接调用。
  3. 加载 .npy 后检查形状为 3×3、元素有限；真机还拒绝文件名包含 dummy，以及与当前画面尺寸生成的占位矩阵在绝对误差 1e-9 内相同的矩阵。

把 H_dummy.npy 改名为 H.npy 不能绕过数值检查。正确做法是重新完成真实标定，而不是伪造文件名。

手动/跟踪互斥与退出

  • 开始跟踪要求机器人已经站立、移动模式就绪、轴流存在且不在过渡态。
  • 开始跟踪会清空手动方向键；跟踪期间方向键输入被拒绝。
  • 按 T、停止按钮、Esc、窗口失焦、Space、回零或切换步态都会先停止跟踪。
  • 停止跟踪调用 robot.stop_tracking()，将 forward/yaw 清零并退出跟踪状态（恢复手动可用）；之后可恢复手动控制。
  • 跟踪线程和看门狗线程停止后会等待释放；界面关闭还会关闭视频与 UDP。

核心概念

证据链优于“看起来成功”

每个实验至少需要四类证据：

  1. 输入：运行命令、参数、机器人 IP、状态端口、现场状态。
  2. 过程：状态三元组、四膝、速度、声纳、界面提示或标定残差。
  3. 结果：动作完成判据、停车判据、退出后姿态。
  4. 安全：清场、扶稳、控制源唯一、停止口令和异常处理。

例如 task06 仅记录“脚本跑完了”不够；应记录点动速度峰值、停车后有效速度样本、forward 归零、收尾归零状态。

故障处理优先级

真机异常按以下顺序处理：

  1. 停：停止目标跟踪、松开方向键、发零轴；紧急时按实验室规程执行软急停、人工扶稳或物理断电。
  2. 稳：保持零值轴流或扶稳，确认机器人不会继续移动或突然失去支撑。
  3. 读：保存终端与界面提示原文，记录当前三元组和状态年龄。
  4. 分：判断是控制链路、状态链路、传感器、视频、标定还是 PID。
  5. 修：只改变一个变量；先离线验证，再从小运动量真机复测。
  6. 记：故障未解决或安全条件不足时，停止实验并报告教师。

常见错误

  • 只记录结果截图，不记录命令、参数和状态序列，导致无法复现。
  • 将 task06 的部分成功、task08 的避障成功或进程退出码当作完整验收。
  • 用增大轴值、延长时间、降低阈值来掩盖网络、标定或状态问题。
  • 把 0.5 s 公共状态新鲜度、0.2 s 视觉帧龄、0.3 s 声纳帧龄、0.5 s 感知超时和 1.0 s 看门狗混为一谈。
  • 将 task12 保留的 lost_confirm=10 字段误认为目标丢失会等待 10 帧；当前安全层立即停车。
  • 认为 --auto-follow 会自动起立；它只自动发起跟踪，启动门控仍要求运动就绪。
  • 认为离线模式能验证声纳保护；--offline 关闭真机声纳门控，只验证视觉与数值链路。
  • 在标定后移动相机或机器人，却继续使用旧 H.npy。
  • 用真人测试避障或跟随停车，造成碰撞风险。
  • 把“单元测试通过”写成“真机安全通过”，忽略现场方向、场地和机械防护验证。
