# Lite3 的 PyBullet 与 MuJoCo 实验

## 学习目标

完成本单元后，学生应能够：

1. 启动并操作 `stage1_pybullet.py`，说明站立、阻尼、安全蹲伏和 trot 四种行为。
2. 启动并操作 `stage2_mujoco_lab.py`，说明站立/蹲伏、摩擦、重力和 150 N 推力实验。
3. 比较 PyBullet `POSITION_CONTROL` 与 MuJoCo 中显式 PD 力矩计算的差异。
4. 解释对角步态的相位关系，以及 `HipY/Knee` 目标如何变化。
5. 按“单变量、先复位、再扰动、后恢复”的方法完成对照实验。
6. 从接触对数、终端日志和画面中提取证据，而不是只凭主观判断“走得好”。

## 建议学时

建议 **8 学时**：教师演示 3 学时，学生实操 5 学时，课堂验收穿插进行。

| 活动 | 学时 |

## 先修知识

- 已完成“物理仿真基础”中的坐标系、四元数、PD 和状态数组学习。
- 了解四足机器人 FL、FR、HL、HR 四个腿组及 HipX、HipY、Knee 三类关节。
- 能在 WSL 中激活 Python 虚拟环境并运行脚本。
- 知道 PyBullet 与 MuJoCo 是两个不同物理引擎，不会共享内存或状态。

## 核心概念

### 两个引擎的共同点与差异

| 项目 | stage1 PyBullet | stage2 MuJoCo |
|---|---|---|
| 模型格式 | URDF | MJCF |
| 初始机身高度 | `0.28 m` | `0.35 m` |
| 站立角 HipY/Knee | `-0.985 / 2.084` | `-0.7 / 1.2` |
| 站立 HipX | 左 `0.1`，右 `-0.1` | 左 `0.1`，右 `-0.1` |
| 主要控制方式 | `POSITION_CONTROL` | 显式 PD 后写 `data.ctrl` |
| 正常步态 | 2 Hz trot | 只有站立/安全蹲伏 |
| 输入 | PyBullet 窗口键 | 查看器字母键或终端输入 |
| 推力 | 150 N，逐步衰减 | 150 N，持续 `0.15 s` |
| 复位 | 恢复摩擦、重力、模式并重置关节 | 恢复摩擦、重力、模式并重置数据 |

两者都连接地面并启用机器人自碰撞，但模型表达、执行器参数和初始条件不同，因此不能期望同一组动作产生完全相同的轨迹。

### stage1 的四种行为

1. **站立**：按基础站姿下发位置目标；站立/trot 的最大电机力参数为 `60`。
2. **trot**：频率 `2.0 Hz`，FL 与 HR 同相，FR 与 HL 反相；运动时还会施加沿机身 x 轴、大小为 `30*|vx|` 的辅助外力。
3. **阻尼**：使用 `VELOCITY_CONTROL`，目标速度为 0，力参数仅 `0.1`，用于被动耗散运动。
4. **安全蹲伏**：`HipY=-1.5`、`Knee=2.6`，最大力参数为 `30`，通过降低姿态增强稳定性。

trot 的膝关节抬腿量为：

```text
0.30 * max(0, -sin(phase))
```

HipY 在基础角上叠加 `0.25*sin(phase)` 和 `0.2*vx`。这是一种脚本式开环步态，不使用状态反馈重新规划落足点。

### stage1 的键位与环境切换

| 操作 | 效果 |
|---|---|
| 上/下方向键 | `move_speed=+1/-1`，松开回 0；非零时进入 trot |
| `1` | 脚部摩擦在 `0.8` 与 `0.01` 间切换 |
| `2` | 重力在 `-9.81` 与 `0` 间切换 |
| `3` | 站立 → 阻尼 → 安全蹲伏循环 |
| 空格 | 在底盘上方 `z=0.1` 处施加 150 N 瞬时推力，之后每步乘 `0.95` |
| `r` | 复位到站姿，同时恢复默认摩擦、重力和模式 |
| 关闭窗口/结束进程 | 退出实验 |

方向键是否有效取决于 PyBullet 窗口是否获得键盘焦点。日志每 120 步打印当前摩擦、重力、接触对数和速度设定。

### stage2 的 PD 控制

`joint_position_ctrl()` 遍历 MuJoCo 执行器，根据执行器名称选择目标关节角，再计算：

```text
ctrl[i] = 40*(target-qpos) - 2*qvel
```

- 站立：`HipY=-0.7`、`Knee=1.2`。
- 安全蹲伏：`HipY=-1.5`、`Knee=2.6`。
- HipX：左腿 `0.1`，右腿 `-0.1`。

这里 `kp=40`、`kd=2`，与 stage1 的 PyBullet 位置控制参数不是同一接口。stage2 还把外力写入名为 `TORSO` 的机身刚体，而不是假定某个固定下标。

### stage2 的输入与推力

| 输入 | 效果 |
|---|---|
| `f` | 所有几何体切向摩擦系数在 `0.02` 与 `0.8` 间切换 |
| `g` | 世界重力 z 分量在 `0` 与 `-9.81` 间切换 |
| `v` | 站立/安全蹲伏切换 |
| `p` | 对 `TORSO` 施加 x 方向 150 N，持续 `0.15 s` |
| `r` | 恢复默认环境并重置仿真数据 |
| `q` | 退出 |

字母可以由 MuJoCo 查看器回调放入队列，也可以在终端输入后按回车。主循环每步只从队列取一个命令，因此不要在短时间内连续快速堆积多个字母。

### 摩擦、重力与接触

- 摩擦系数影响接触处抵抗相对滑动的能力，低摩擦不直接改变重力方向。
- 零重力消除了维持站立所需的主要载荷，但不会自动把速度、位置或关节角清零。
- 接触对数是接触约束数量，不是“几只脚稳稳着地”的直接计数。
- 机器人发生摔倒后，单纯等待不会恢复站姿；应先按 `r` 再开始下一组对照。

### 推力实验的公平比较

要比较两种引擎，至少应记录：

1. 推力大小与方向；
2. 作用点和作用对象；
3. 持续时间与衰减规律；
4. 实验开始时的姿态、速度和高度；
5. 复位后到施力之间的等待时间。

本课程脚本的这些条件并不完全相同，所以结论应表述为“在当前脚本设置下观察到……”，不能泛化为“MuJoCo 一定比 PyBullet 更抗推”。

## 教师演示

### 演示 1：PyBullet 基础站立与 trot

```bash
cd ~/lite3_lab/simulation
source .venv/bin/activate
python3 stage1_pybullet.py
```

演示顺序：

1. 保持站立，确认初始高度 `0.28`、默认站姿和接触日志。
2. 点按 PyBullet 窗口后按上方向键，观察进入 trot；松开后回到站立。
3. 按 `3` 切到阻尼，再切到安全蹲伏，比较机身高度。
4. 按 `r` 复位，确认日志和模式恢复。
5. 按空格施加 150 N，说明推力作用点和逐次衰减。

### 演示 2：PyBullet 环境扰动

1. 按 `1` 切换低摩擦，再按方向键，观察脚底滑移。
2. 复位后按 `2` 切换到零重力，再按 `3` 观察姿态变化。
3. 再次复位，说明“先复位”可以避免上一组实验残留状态影响下一组。

### 演示 3：MuJoCo 站立、蹲伏与输入线程

另开终端：

```bash
cd ~/lite3_lab/simulation
source .venv/bin/activate
python3 stage2_mujoco_lab.py
```

演示顺序：

1. 在查看器或终端输入 `v`，比较站立与安全蹲伏。
2. 输入 `f`、`g`，说明所有几何体摩擦与世界重力被修改。
3. 输入 `p`，强调 150 N 持续 `0.15 s`，不是 stage1 的指数衰减。
4. 输入 `r`，确认高度恢复为 `0.35` 且环境变量恢复默认。
5. 输入 `q` 正常退出，避免直接关闭承载 ROS2 或查看器的终端。

### 演示 4：从日志提取证据

指导学生定位以下日志字段：

- stage1：`step`、`μ`、`g`、`接触对数`、`速度`。
- stage2：`step`、`μ`、`g`、`接触对`、`模式`。

特别说明：日志中的“速度”在 stage1 是 `move_speed` 设定值，不是通过状态数组测得的真实底盘速度。

## 学生实操

### 任务 1：基础操作清单

分别完成：

- stage1：站立 → trot → 阻尼 → 安全蹲伏 → 复位 → 退出。
- stage2：站立 → 蹲伏 → 低摩擦 → 零重力 → 推力 → 复位 → 退出。

每项操作记录键名、输入位置（窗口或终端）、画面变化和日志变化。

### 任务 2：单变量实验矩阵

每个引擎至少完成四组实验，严格按“复位 → 等待稳定 → 改变一个变量 → 观察 → 复位”的顺序。

| 引擎 | 实验 | 保持不变的量 | 记录证据 |
|---|---|---|---|
| PyBullet | 正常/低摩擦站立 | 重力、模式、推力 | 滑移、接触数、复位状态 |
| PyBullet | 正常/零重力 | 摩擦、模式 | 高度变化、脚部状态 |
| PyBullet | 站立/阻尼/蹲伏 | 摩擦、重力 | 姿态、高度 |
| PyBullet | trot 前/后 | 频率、地面 | 对角相位、设定速度 |
| MuJoCo | 正常/低摩擦站立 | 重力、模式 | 接触数、滑移 |
| MuJoCo | 正常/零重力 | 摩擦、模式 | 高度变化 |
| MuJoCo | 站立/安全蹲伏 | 摩擦、重力 | 高度、PD 控制 |
| MuJoCo | 推力后恢复 | 姿态、作用点 | 偏移方向、恢复时间 |

### 任务 3：步态相位分析

对 stage1 trot 回答：

1. FL 与哪些腿同相？
2. FR 与 HL 的相位差是多少？
3. 膝关节在哪个半周期抬升？
4. `vx` 改变时，HipY 目标中的哪一项随之改变？
5. 为什么松开方向键后速度设定回零，但机器人可能仍因惯性短暂运动？

### 任务 4：两份简短实验记录

每份记录包含：

- 引擎、脚本名、运行日期；
- 初始姿态和环境参数；
- 只改变的一个变量；
- 至少一个画面现象和一条日志证据；
- 复位操作及复位后的状态；
- 结论与不确定因素。

## 思考题

1. PyBullet 的 `POSITION_CONTROL` 与 stage2 的 PD 力矩计算有什么接口差异？
2. 为什么阻尼模式适合观察被动耗散，而不适合作为主动行走控制器？
3. 安全蹲伏为什么可能提高抗扰能力？是否意味着膝角越大越好？
4. 零重力下接触对数下降是否说明摩擦也失效了？
5. 为什么“150 N 推力”不能脱离持续时间、作用点和衰减规律来比较？
6. stage1 日志中的 `move_speed` 与真实速度有什么差别？
7. MuJoCo 输入线程为何只负责入队，而主循环负责执行命令？
8. 如果每次实验前不复位，哪些变量可能残留并污染结论？

## 验收标准

| 验收项 | 合格标准 |
|---|---|
| 启动与退出 | 两个脚本均能独立启动，使用正确键位复位和退出 |
| 行为识别 | 正确说明 stage1 站立、trot、阻尼、安全蹲伏及 stage2 两种姿态 |
| 控制接口 | 能区分 PyBullet 位置控制与 MuJoCo 显式 PD 力矩 |
| 参数识读 | 正确写出两阶段站姿、PD 参数和推力差异 |
| 单变量实验 | 每个结论只归因于一个改变量，并包含复位步骤 |
| 证据记录 | 同时提供画面/状态现象与日志字段，不只写“稳定/不稳定” |
| 步态分析 | 正确指出 FL/HR 同相、FR/HL 反相及膝抬升半周期 |
| 安全习惯 | 每组实验结束复位，不在模型摔倒后继续叠加扰动 |

## 常见错误

- **方向键无效就反复按脚本内键**：先点击 PyBullet 窗口获得焦点；stage1 与 stage2 键位体系不同。
- **在 stage2 使用数字键切换摩擦/重力**：stage2 使用 `f/g/v/p/r/q`。
- **终端输入后没有回车**：终端输入线程通过 `input()` 读取，需要回车；查看器字母回调不需要。
- **同时运行两个 PyBullet/MuJoCo GUI 后混淆日志**：给终端标注脚本名，只操作当前窗口。
- **把 stage2 的 `40/2` 当成 stage3 的 PD 参数**：stage3 使用 `30/1`，不能跨阶段照搬。
- **把 150 N 当作相同冲量**：stage1 逐步衰减，stage2 固定持续 0.15 秒，需分别分析。
- **认为 `r` 只重置位置**：它还会恢复摩擦、重力、控制模式和推力状态。
- **用接触对数直接等于落脚数**：接触点可能分布在同一脚掌或存在自碰撞接触。
- **忽略真实速度与设定速度的区别**：`move_speed` 只表示输入目标，不代表测量结果。
- **在零重力或摔倒后继续同一实验**：应先复位，否则后续姿态不可比。
