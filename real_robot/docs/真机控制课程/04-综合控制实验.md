# Lite3 综合控制实验

## 学习目标

本单元覆盖 task07、task08、task09、task10。完成后学生应能够：

1. 执行持续前进，观察速度与位置，并确认停车窗口内真正停稳。
2. 理解 task08 的前后超声波保护：近障或数据无效时停止前进轴，但不自动绕障。
3. 验证前进、后退、左移、右移的轴值与身体速度符号。
4. 使用 task10 完成键盘移动、姿态切换、低速步态、回零和状态观测。
5. 解释 task10 的前后防撞、侧移风险、状态门控以及 Esc/失焦停车。
6. 准确说明 task09 当前没有发送偏航转向轴，不能把“四向移动”误认为“已学会转向”。

## 建议学时

建议 **4 学时**：task07/task08 联合演示与学生实操 2 学时，task09 符号验证 1 学时，task10 界面与安全复盘 1 学时。每项运动均需分组轮换，不安排同时操作同一机器人。

## 先修知识

- 已通过 task01/task02 的链路与只读观测验收。
- 已完成 task03 起立/趴下/归零和 task05 移动准备。
- 已通过 task06 点动，能够独立判断方向与停车。
- 理解前向/侧向/偏航三个轴、死区、零值轴流和状态新鲜度。
- 能使用 Tkinter 图形界面，理解按住/松开按键与窗口焦点。

## 核心概念

### 持续前进与停车窗口

task07 默认 `forward=9000`、运动 3 s、停车观察 3 s，轴流默认 30 Hz。安全停车函数接收 `--cooldown`，在观察窗口内寻找 `abs(vel_body[0]) < 0.02 m/s`；只有方向和停车都确认才返回成功。

task07 启动门控与基础任务不同：

- 当前为 `(1,0,0)` 或 98 时允许继续进入自身起立流程。
- 当前为其他状态时，先调用 `ensure_home()`；必须确认归零并回到 `(1,0,0)` 才继续，否则停止任务。

这是“未知/移动中间状态不得直接起步”的保护，不应通过关闭状态监听绕过。

### 超声波保护不是自动导航

task08 在每个控制循环读取前/后声纳：

- 前或后距离小于 1.0 m：forward 轴归零，保持原地运动。
- 任一距离不是有限数：也按阻塞处理。
- `get_state()` 返回 `None`：forward 轴归零，并提示状态未知。
- 两侧均恢复到不小于 1.0 m：继续发送原 forward 轴值。
- 避障/阻塞时间仍计入 `duration`，不会暂停计时延长总时长。

它**不会绕行、不会侧移、不会倒车，也不会自动退出任务**。这里的“原地运动”是继续发送零轴流并保持步态，不应理解为位置绝对不变。

`task08` 还有两个必须如实讲授的实现细节：

1. `--cooldown` 参数虽然存在，但当前调用没有把它传给 `_safe_stop()`；安全停车函数内部硬编码观察上限 **5.0 s**。
2. 当检测到过障且已停稳时，即使没有采集到正向速度样本，也可能返回避障成功；若方向正确但未停稳，当前代码仍可能返回 `True`。验收必须单独核对停车日志。

### 四向轴值与坐标

task09 使用固定轴值：

| 动作 | forward | lateral | 预期身体速度 |
|---|---:|---:|---|
| 前进 | +12000 | 0 | `vel_body[0]` 为正 |
| 后退 | -12000 | 0 | `vel_body[0]` 为负 |
| 左移 | 0 | -16000 | `vel_body[1]` 为负 |
| 右移 | 0 | +16000 | `vel_body[1]` 为正 |

每段运动 3 s，随后 forward/lateral 归零并保持轴流 2 s。yaw 始终为 0。

**task09 文件名中的 directions 指四向平移；当前实现不验证偏航转向符号。** 真正的偏航输出在 task12 中，需要通过悬挂、小幅度、短时真机试验单独确认。

### task10 的控制架构

- `task10_gui.py`：Tkinter 界面、按键绑定、RTSP 显示、状态刷新。
- `task10_robot.py`：UDP 控制、姿态状态机、30 Hz 三轴流、手动/跟踪互斥和前后防撞。
- `task10_video.py`：后台读取 RTSP，断流后每 2 s 尝试重连。
- task10 界面中的“开始跟踪（T）”会加载 `FollowSession`，即使用户运行的是 task10 入口，跟踪功能仍来自 task12。

GUI 的状态刷新周期为 50 ms，但状态数据仍受公共 `get_state()` 的 0.5 s 新鲜度限制；界面看起来在刷新，不代表机器人数据也新鲜。

## 教师演示步骤

1. 在稳定趴下状态运行 task07 默认参数，逐段解释启动门控、起立、移动准备、前进、停车和收尾。
2. 重点展示停车日志：`forward 归 0` 后仍需轴流保活，看到 `abs(vel)<0.02` 才记录停稳时刻。
3. 演示 task08：在开始前布置一个不会接触机器人、但能使前或后距离小于 1.0 m 的固定障碍物；不要让人手持障碍物站在机器人路径上。
4. 展示 task08 从“前进”切换为“原地运动”，再安全移开固定障碍物后恢复；提醒阻塞时计时继续。
5. 运行 task09，逐段让学生根据轴值和 `vel_body` 判断方向；明确指出四段中 yaw 都是 0。
6. 启动 task10，先只读观察，再依次演示空格起立/准备移动模式、按住方向键、松开、Esc、失焦和停止按钮。
7. 演示“趴下时方向键禁用”和“状态帧过期时清空按键”，不通过拔线方式制造突然失速。
8. 演示回零按钮只允许在 `(1,0,0)` 或 98 启动，并等待 17→1；站立状态需先按空格趴下。
9. 演示关闭窗口：先退出跟踪、停止运动、视频关闭、控制器关闭；强调关闭 GUI 不等于自动趴下归零。

## 学生实操步骤

### task07：持续前进与停车观察

**目标**：从零轴流切换到持续前进，再恢复零轴流并确认停稳。

**学生操作**

```bash
python3 task07_axis_stream_forward.py --duration 3 --cooldown 3
```

1. 前后至少 2 m 清场，护架或安全员扶稳；确认没有第二个控制源。
2. 运行命令。若启动时不是趴下或 98，观察自动归零门控是否成功；归零失败则停止，不绕过。
3. 记录前进期 `vel_body[0]` 峰值、均值、位置起止值和状态三元组。
4. 停车阶段记录 forward 归零时间、停稳时间和停车后速度。
5. 若未停稳，保持现场安全并记录失败；不要立即再次运行。
6. 收尾确认趴下、观察到 17、回到 1。

**验收标准**

- 前进期速度峰值大于 `0.02 m/s`，方向为正。
- `--cooldown` 为大于 0 的值，停车窗口内实际观察到 `abs(vel)<0.02`。
- 终端报告“方向正确 + 已停稳”，不只是“前进完成”。
- 收尾完成，机器人最终稳定趴下。
- 位置差仅作为 IMU 积分参考，不宣称是精密测量。

**常见错误**

- 将 `--duration 0` 当作“很快结束”：它表示一直前进到 Ctrl-C，只适合教师演示。
- 只延长 duration 不检查场地：默认注释中的距离估计不是任何现场的安全保证。
- `--state-port 0`：task07 明确拒绝，因为启动门控需要状态。
- Ctrl-C 后马上松开扶稳：应等待零轴停车和收尾完成。

### task08：超声波保护前进

**目标**：验证前后近障、无效数据和状态缺失时 forward 被拦截，理解恢复条件。

**学生操作**

```bash
python3 task08_ultrasonic_guard_forward.py --duration 5
```

1. 先在 task02 中读取前/后基线，确认两侧读数有限且场地安全。
2. 若演示避障，在运动开始前将一个固定障碍物放入声纳可检测区域，使前或后距离小于 1.0 m，并保证机器人不会接触到它。
3. 运行任务，记录“前进/原地运动”的模式切换、距离和 forward 行为。
4. 需要演示恢复时，先按教师口令停止运动，再由安全员在机器人稳定后移开障碍物；不要在机器人仍运动时进入路径。
5. 单次演示也可从“已阻塞”开始，观察原定时长结束后停稳；这种情况不要求产生前进速度峰值。
6. 记录终端实际停车观察时间，认识内部 5 s 上限与 `--cooldown` 参数未接入的差异。

**验收标准**

- 任一侧小于 1.0 m 或数据无效时，日志报告告警，forward 轴归零。
- 两侧安全且状态有效时，日志显示恢复前进。
- 状态帧缺失时，forward 轴归零，不继续盲目前进。
- 最终有有效停车观察，机器人停止运动并完成收尾。
- 学生明确说出“没有自动绕障/侧移/倒车”，且总运行时间不因阻塞暂停。

**常见错误**

- 用真人测试碰撞或不断靠近机器人：使用固定障碍物，人员不得进入运动路径。
- 把“原地运动”理解为姿态完全锁定：它仍维持步态，可能有轻微身体运动。
- 把 task08 当作侧向避障：左右方向不受本任务保护。
- 修改 `--cooldown` 后期待停车窗口改变：当前安全停车内部固定为 5 s。
- 看到“~方向正确”就当停稳：仍需人工核对停车速度。

### task09：前后左右方向与符号

**目标**：验证四个平移方向的轴符号和身体速度符号。

**学生操作**

```bash
python3 task09_axis_directions.py
```

1. 扩大前后左右净空，重点确认左右没有超声波防护。
2. 从稳定趴下开始；task09 没有 task07 那样的启动归零门控，教师应提前完成状态确认。
3. 运行固定序列，逐段记录 `vel_body=(vx,vy)` 与 `pos_world=(x,y)`。
4. 每段 3 s 后确认 forward/lateral 已归零，且程序继续发送 2 s 零轴流。
5. 若状态帧在运动中丢失，代码的 `_run_direction()` 只是跳过打印，**不会自动把当前轴归零**；应立即由安全员 Ctrl-C 或按实验室停止规程处理。
6. 收尾确认趴下与归零。

**验收标准**

- 前进 `vx>0`、后退 `vx<0`、左移 `vy<0`、右移 `vy>0`，与代码轴值一致。
- 每段之间有明确的零轴停顿，无连续反向叠加。
- 能指出 yaw 始终为 0，未完成转向验证。
- 收尾完成；若方向不符，记录异常并停止，不在现场随意改轴值重试。

**常见错误**

- 只观察机器人朝向：应看身体速度与位置符号。
- 认为 task09 包含左转/右转：当前没有 yaw 指令。
- 状态丢失仍等待 3 s 结束：当前方向函数不会因缺状态自动归零，应立即安全停止。
- 侧移时只看前后距离：侧方必须人工清场。

### task10：键盘、视频、状态与控制面板

**目标**：在图形界面中完成受门控保护的手动低速控制。

**学生操作**

```bash
python3 task10_gui.py
```

1. 确认 RTSP 地址可访问、状态端口有效；本入口要求 `--state-port > 0`。
2. 启动后观察状态、姿态、前后距离、身体速度和防撞提示。视频断流时界面显示错误并自动重连，但状态控制是另一条链路。
3. 首次在趴下状态按 Space：程序起立并自动准备移动模式、启动零轴流、切低速步态，等待“站立就绪”。
4. 按住方向键移动，松开立即将对应轴清零。可测试相反方向同时按下时，其差值计算会抵消该轴；课堂按一次一个方向练习。
5. 演示前方近障只拦截前进、后方近障只拦截后退；不要用真人做移动障碍。
6. 按 T 启动/停止 task12 跟踪；首次启动需要 YOLO 权重和标定文件。跟踪时方向键被禁用，先按 T 或停止按钮退出。
7. 测试 Esc、窗口失焦和“停止运动”按钮，确认运动轴归零且跟踪停止。
8. 需要趴下时按 Space；在 `(1,0,0)` 使用“回零”并等待 17→1。98 状态也允许回零按钮发送命令，但仍须观察状态序列。
9. 关闭窗口前按 Space 趴下并完成所需归零。正常关闭会停运动、关视频和 UDP，但不会替你执行趴下/归零。

**验收标准**

- 未就绪、趴下、姿态未确认或状态过期时，方向键不能产生有效运动。
- 前进受前方 1.0 m 阈值保护，后退受后方 1.0 m 阈值保护；左右侧移无测距拦截。
- 松开方向键、Esc、失焦、停止按钮均能停止运动并清空按键状态。
- 跟踪与手动互斥，停止跟踪后恢复手动可用状态。
- 能完成起立、低速移动、趴下和回零，并读懂界面状态。
- 默认只使用平地低速步态；其他步态选项只作代码认识，不在本实训中自行提速。

**常见错误**

- 在跟踪中按方向键：手动输入会被拒绝；先退出跟踪。
- 视频有画面就以为控制可用：控制依赖状态帧与姿态门控，不依赖视频。
- 左右移动不报警就以为安全：那是无侧向测距保护，必须人工确认。
- 站立状态直接点回零：会被拒绝，先按 Space 趴下。
- 关闭窗口代替收尾：关闭只停止/释放资源，不自动完成姿态归零。
- 把 task10 当作无机器人离线模拟：现行 task10 入口是真机控制；脱机视觉验证使用 task12 `--offline`。

## 思考题

1. task07 的 `--cooldown` 如何影响停车判定？为什么不能把“计时结束”当作“已停稳”？
2. task08 为什么在声纳无效时也停止前进轴？失效安全与正常运行有何区别？
3. task08 的避障是否构成路径规划？它有哪些不能完成的行为？
4. task09 四个动作的 forward/lateral 符号是什么？为什么 yaw=0 意味着没有验证转向？
5. task09 在状态帧丢失时继续当前轴值，与 task08 状态丢失时 forward 归零，有何差异？操作员应如何应对？
6. task10 的前后防撞为什么不能保护侧移？若同时按前进与右移会发生什么？
7. 为什么 Esc 和窗口失焦需要同时停止跟踪与运动，而不能只清方向键？
8. task10 回零按钮与公共 `ensure_home()` 的起点确认有何异同？为什么要等待 17 再等待 1？

## 验收标准

| 任务 | 量化/行为要求 | 必需安全证据 |
|---|---|---|
| task07 | 默认 3 s 前进；点动峰值大于 0.02 m/s；cooldown 内 `abs(vel)<0.02` | 启动门控通过，收尾归零完成 |
| task08 | 近障/无效/缺状态时 forward=0；安全时恢复；阻塞计时继续 | 固定障碍演示，无人员进入路径，停车日志有效 |
| task09 | 四个方向轴值与 `vel_body` 符号一致；每段后停 2 s | 四侧清场，明确未做 yaw 验证，收尾完成 |
| task10 | 就绪门控、前后阈值、松键/Esc/失焦停车、姿态与回零 | 侧移人工看护，跟踪/手动互斥，退出前姿态安全 |

综合实验不以“跑完脚本”作为通过条件。任一动作方向错误、停车未确认、绕过启动门控或让人员进入运动路径，均需暂停并重新讲解后再测。

## 常见错误汇总

| 现象 | 代码/操作原因 | 排障与整改 |
|---|---|---|
| task07 启动即停止 | 当前状态不是 1/98，自动归零失败 | 查看 ensure_home 日志，恢复稳定趴下后重跑 |
| task07 显示未停稳 | cooldown 不足、惯性或其他控制源 | 保持零轴流，延长观察，排查多客户端 |
| task08 一直原地运动 | 前/后小于 1 m、读数无效或状态过期 | 停止后检查固定障碍与状态链路 |
| task08 修改 cooldown 无效 | 参数未传入 `_safe_stop()` | 认识当前 5 s 内部上限，按实际日志评价 |
| task09 状态丢失仍运动 | 当前方向循环不因无状态自动归零 | 立即安全停止，恢复链路后再试 |
| task09 期待原地转向 | yaw 轴固定为 0 | 转至 task12 的受控偏航验证 |
| task10 方向键无反应 | 趴下、未准备、过渡态或状态过期 | 查看姿态与状态提示，先按 Space 准备 |
| task10 跟踪时手动失效 | 设计为手动/跟踪互斥 | 按 T 或停止按钮退出跟踪 |
| task10 左右移动无警报 | 没有侧向超声波保护 | 人工清场，不修改为“看似安全” |
| task10 关闭后仍站立 | 关闭不自动趴下/归零 | 下次操作前先按 Space 收尾并确认状态 |
