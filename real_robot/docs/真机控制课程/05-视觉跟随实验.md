# Lite3 人体视觉跟随实验

## 学习目标

本单元以 task12 为唯一教学入口。完成后学生应能够：

1. 说明“视频采集 → YOLO 人体检测/跟踪 → 脚点像素 → 单应反投影 → 地面距离/偏角 → PID → 轴值”的完整链路。
2. 按近左、近右、远右、远左顺序完成四点单应标定，并检查凸四边形和重投影残差。
3. 使用 `--selfcheck` 与 `--offline` 在无运动条件下验证数值和视觉链路。
4. 解释并验收视觉帧龄、感知链路超时、独立看门狗、声纳帧龄、目标距离迟滞和前后防撞。
5. 解释双环 PID、死区、输出斜率限制、轴值缩放与零值保持。
6. 在真机模式下拒绝 dummy 单应矩阵，按规范完成悬挂验证、小幅度跟随和安全退出。
7. 说明 task11 已并入 task12，`legacy/task11_follow.py` 不是实验入口。

## 核心概念

### 当前入口与资源

task12 复用 task10 的 GUI、机器人控制器和视频线程。默认资源为：

| 资源 | 默认路径 | 用途 |
|---|---|---|
| 真实单应矩阵 | `assets/H.npy` | 真机与正式离线反投影 |
| 占位矩阵 | `assets/H_dummy.npy` | 仅帮助理解占位数据；`--dummy-h` 实际会按画面尺寸现场生成等价占位矩阵 |
| YOLO 权重 | `assets/yolov8n.pt` | YOLOv8 nano 人体检测/跟踪 |
| 默认 RTSP | `rtsp://192.168.1.120:8554/test?tcp` | 机器人视频流 |

依赖由 `requirements.txt` 管理，GUI 还需要 Tkinter。资源文件存在不等于标定与当前相机姿态匹配，也不等于模型在课堂光线下表现合格。

### 四种运行模式

| 命令/模式 | 行为 | 运动风险 |
|---|---|---|
| `--selfcheck` | 在加载 GUI 前执行 PID/死区数值断言 | 不访问相机、不连接机器人、不发运动命令 |
| `--offline` | 显示真实视频的检测、框、脚点、地面距离；控制器不启用真机心跳/状态/运动 | 不发真机运动指令；声纳不参与门控 |
| `--offline --dummy-h` | 用占位矩阵做脱机管线演示 | 距离/偏角不代表真实地面测量，仅用于链路教学 |
| 真机（可加 `--auto-follow`） | 复用 task10 控制器，先要求站立且移动模式就绪 | 会发送前进与偏航轴，必须现场防护 |

`--auto-follow` 在 GUI 启动约 500 ms 后尝试自动开始跟踪，不会自动起立。若机器人尚未准备移动模式，启动会失败并提示。首次课堂演示建议不加该参数，人工按 T 开始。

### 目标选择与脚点

`TargetTracker` 仅检测 `classes=[0]`（人体），默认置信度为 0.5：

- 首次未锁定目标时，选择检测框水平中心最接近画面中心的人。
- 锁定后按 YOLO track ID 持续寻找同一个人。
- 跟踪点取检测框底边中点 `(cx, y2)`，不是框中心，也不是人体头部。
- 检测框坐标非有限值时按无目标处理。
- tracker 在无 ID 或锁定目标消失时增加丢失计数，超过 10 次清除锁定 ID；但跟随安全层只要当前无目标就立即停车。

### 地面标定与单应反投影

标定要求四个地面标记与相机画面中的四个点一一对应。代码使用 3×3 单应矩阵 `H`：

```text
[u, v, 1]^T → H × [u, v, 1]^T → 除以第三项 → [X, Y, 1]
```

默认地面坐标为：

| 顺序 | 标记 | 地面坐标 |
|---|---|---|
| 1 | 近左 | (-1, 1) |
| 2 | 近右 | (1, 1) |
| 3 | 远右 | (1, 3) |
| 4 | 远左 | (-1, 3) |

原点位于机器人地面投影，X 向右、Y 向前，单位由代码定义为米。教师必须用卷尺按这套坐标实际布点，不能把图中“看起来相近”的位置直接写成 1 m/3 m。

代码要求源点和目标点都是顺序一致的凸四边形，允许整体顺时针或整体逆时针，拒绝交叉、自交或退化点序。求解后计算四个点的重投影残差，最大残差大于 **0.005 m** 时拒绝保存。

地面投影模型以“脚点位于同一平面”为前提。检测框底边如果落在台阶、椅子或遮挡物上，反投影距离可能明显错误；课堂应选择平整地面、完整人体和稳定光照。

### 双环 PID 与坐标误差

对目标脚点反投影得到 `(lateral, forward)` 后：

- 前向距离 `distance = forward`；`forward <= 0` 或坐标非有限时立即停车。
- 偏航误差 `error_x = atan2(lateral, forward)`，单位为弧度；目标在右时误差为正。
- 偏航环使用滤波后的误差、比例项和微分项。
- 距离环使用 `distance - target_distance` 的比例项与积分项。

`DualLoopPID` 的默认参数如下：

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `target_distance` | 2.0 m | 期望跟随距离 |
| `kp_yaw` / `kd_yaw` | 0.6 / 0.25 | 偏航比例/微分 |
| `tau` | 0.15 s | 偏航误差低通滤波时间常数 |
| `kp_vx` / `ki_vx` | 0.5 / 0.05 | 距离比例/积分 |
| `max_integral` | 5.0 | 距离积分限幅 |
| `vx_min` / `vx_max` | -0.2 / 0.4 | 前向速度输出范围 |
| `wz_max` | 0.25 | 偏航角速度输出范围 |
| `yaw_deadzone` | 0.06 rad | 偏航误差死区 |
| `dist_deadzone` | 0.10 m | 距离误差死区 |
| `dvx_max` | 0.15 | 每标准 0.05 s 周期的最大速度变化 |
| `dwz_max` | 0.5 | 偏航输出变化斜率参数 |
| `WZ_SIGN` | +1 | 偏航输出符号；真机必须验证 |

距离积分只在距离误差绝对值大于或等于 0.10 m 时更新；死区内输出速度为零，但已有积分不会自动清零。调用 `update(..., active=False)`、重置或停车时会同时清零滤波、积分和历史输出。

首次更新使用 `dt=0.05 s`，之后按单调时钟计算，`dt` 限制在 0.01～0.5 s。偏航微分使用滤波后误差的变化率；滤波系数随 `dt` 改变。速度与角速度还有输出斜率限制，避免误差突变时立即给出大幅轴值。

### 从 twist 到轴值

默认缩放：

- 前向：`vx × 40000`。
- 偏航：`wz × 65534`。
- 侧向：跟随始终为 0。

`_axis_value()` 将结果四舍五入并限制在 ±32767。若结果是非零但落在死区内，会改为死区外一单位：

- 前向最小非零绝对轴值为 **6554**。
- 偏航最小非零绝对轴值为 **9554**。
- 零输入始终输出零。

这一步保证低速后退和转向能越过固件死区，但**不能证明方向正确**。`pid_selfcheck()` 最后明确提示：偏航符号需悬挂测试真机确认。

### 视觉帧龄与独立看门狗

视频线程每次成功 `capture.read()` 后记录 `time.monotonic()`。跟随循环通过 `latest_with_timestamp()` 取回帧及其**采集时间**：

- 无帧或时间戳不大于 0：安全停车。
- 帧龄为负或大于 **0.2 s**：安全停车。
- 每轮循环开始刷新 `_last_update`；独立线程每 **0.05 s** 检查一次。
- 最近一次控制循环更新超过 **1.0 s**：轴归零、调用 `stop_tracking()` 退出跟踪状态（恢复手动可用）、结束会话。

帧龄解决“反复读取同一旧帧”的问题；看门狗解决“整个控制循环或推理卡住”的问题。两者不能互相替代。

`SafetySupervisor.link_timeout=0.5` 还检查最近一次成功 `tracker.update()` 的距离；超过 0.5 s 返回感知链路超时。目标为空但 tracker 正常返回时，该计时仍会刷新，随后由目标丢失规则立即停车。

### 声纳帧龄与距离迟滞

task12 从 `robot.snapshot()` 同时取得前声纳和 `state_age`，再调用：

```text
update_ultrasonic(distance, age)
us_stamp = 当前单调时间 - age
```

因此声纳时间始终对原始状态帧负责，不会因为读取 snapshot 而变新。

真机跟随要求：

- 状态原始帧龄不大于 **0.3 s**。
- 前声纳存在、有限且大于 0。
- 前声纳小于 1.0 m 时进入阻塞，大于 1.3 m 时解除。
- 阻塞时决策为 `STOP`，不是仅禁止前进。

视觉目标距离使用另一组迟滞：

- 小于 1.0 m：进入“过近”；大于 1.3 m：解除。
- 大于 3.5 m：进入“过远”；小于 3.0 m：解除。
- 过近：`ONLY_TURN`，前进轴为 0，只允许偏航。
- 过远：`STOP`。
- 1.0～3.5 m 之间且未处于迟滞状态：正常双环控制。

迟滞可减少阈值附近的频繁切换。task10 控制器还有第二层保护：跟踪前进受前声纳 1.0 m 阈值约束，跟踪后退受后声纳约束；一旦触发，forward 与 yaw 都归零，比 `ONLY_TURN` 更保守。

### dummy 三重拦截

真机不得使用占位矩阵。当前实现从三个层次拦截：

1. 命令行：`--dummy-h` 不同时带 `--offline` 时直接报错。
2. `FollowSession.start()` 再次检查 dummy 标志与真机模式，防止绕过入口直接调用。
3. 加载 `.npy` 后检查形状为 3×3、元素有限；真机还拒绝文件名包含 `dummy`，以及与当前画面尺寸生成的占位矩阵在绝对误差 1e-9 内相同的矩阵。

把 `H_dummy.npy` 改名为 `H.npy` 不能绕过数值检查。正确做法是重新完成真实标定，而不是伪造文件名。

### 手动/跟踪互斥与退出

- 开始跟踪要求机器人已经站立、移动模式就绪、轴流存在且不在过渡态。
- 开始跟踪会清空手动方向键；跟踪期间方向键输入被拒绝。
- 按 T、停止按钮、Esc、窗口失焦、Space、回零或切换步态都会先停止跟踪。
- 停止跟踪调用 `robot.stop_tracking()`，将 forward/yaw 清零并退出跟踪状态（恢复手动可用）；之后可恢复手动控制。
- 跟踪线程和看门狗线程停止后会等待释放；界面关闭还会关闭视频与 UDP。

## 教师演示步骤

### 离线准备

1. 在项目根目录检查资源与依赖：

```bash
cd ~/lite3_lab/real_robot
source .venv/bin/activate
python3 -c "from pathlib import Path; import cv2, numpy, PIL; print([p.name for p in Path('assets').iterdir()])"
```

2. 运行数值自检：

```bash
python3 task12_follow.py --selfcheck
```

预期检查项包括：目标在右时偏航输出符号符合 `WZ_SIGN`、目标偏远时前进、目标偏近时后退、死区输出零、非 active 时积分清零、首周期斜率受限、后退轴越过死区。全部断言通过才进入视觉链路。

3. 运行真实标定文件的离线链路：

```bash
python3 task12_follow.py --offline
```

让一名学生站在相机画面中，观察人体框、脚点、`distance` 与状态文字。强调此时只做显示，不发送真机运动命令，声纳保护关闭。

4. 运行占位矩阵演示：

```bash
python3 task12_follow.py --offline --dummy-h
```

比较距离与真实标定离线结果的差异，说明 dummy 只验证代码管线，不验证实际米制距离。

5. 演示 dummy 拒绝。在机器人趴下、现场受控时运行下列命令，预期在进入跟踪前报错：

```bash
python3 task12_follow.py --dummy-h
```

不进入 GUI，不按 T，不启用心跳或运动。

### 真实标定

1. 保持相机与机器人相对位置固定，之后不再移动相机或机器人底座。
2. 用卷尺在地面布置四点，坐标严格按 `(-1,1)、(1,1)、(1,3)、(-1,3)` 设置；标记应清晰且不被人体长期遮挡。
3. 备份现有 `H.npy` 后再开始，避免误覆盖：

```bash
cp assets/H.npy assets/H.npy.before-calibration
```

4. 运行：

```bash
python3 task12_follow.py --calibrate
```

5. 等待单帧视频，在 `Calibration` 窗口按近左、近右、远右、远左顺序左键点击。右键或 R 清除，Esc 中止。
6. 只有终端提示四点为凸四边形、求解成功、最大重投影残差不大于 0.005 m 并保存成功，才记为标定有效。
7. 重新运行 `--offline`，用已知地面位置检查反投影是否合理。若站立位置变化导致脚点不在地面，应重新理解误差来源，不能盲目调 PID。

### 真机安全验证

1. 使用悬挂或护架限制机体，前后至少 2 m 清场，左右路径额外清场；安全员全程扶稳，人员不站在机器人碰撞路径上。
2. 启动 `python3 task12_follow.py`，先按 Space 起立并等待“运动就绪”。
3. 不站入跟随路径，按 T 开始搜索；无目标时应立即停车。记录“目标丢失，已停车”的出现。
4. 先让目标从画面右侧小幅进入，验证偏航是否向正确方向旋转；若方向反，立即停止，由教师检查 `WZ_SIGN` 与坐标约定。本课程不现场修改代码。
5. 在悬挂条件下进行极短时低速距离跟随，观察 vx 正负、过近/过远迟滞和声纳提示。
6. 演示 Esc、失焦、T 和停止按钮四种退出，确认每次运动轴归零、跟踪退出、手动可恢复。
7. 不通过遮挡相机、拔网线或让推理长时间卡死来验证运动中的看门狗；此类故障注入先做离线/单元测试，真机只在稳定悬挂且无目标静止条件下由教师执行。
8. 结束前停止跟踪、按 Space 趴下，再按任务要求归零并确认状态。

## 学生实操步骤

### 第一步：数值自检

1. 运行 `python3 task12_follow.py --selfcheck`。
2. 保存完整输出，逐项对应七项断言。
3. 回答：为什么“目标偏近应后退”和“后退轴越过死区”是两个不同检查？
4. 自检失败时先检查依赖与文件是否被改动，不进入真机。

### 第二步：离线视觉链路

1. 运行 `python3 task12_follow.py --offline`，确认检测到人体且跟踪 ID 尽量稳定。
2. 记录目标在画面左、中、右三种位置时的偏角趋势和距离显示。
3. 让目标暂时离开画面，确认显示“目标丢失，已停车”；离线模式没有真机轴可停，但状态逻辑仍执行。
4. 比较 `--offline --dummy-h` 与真实 `H.npy` 的距离结果，说明占位矩阵不能用于真机。
5. 检查框底边是否确实落在地面脚点；若是床面、椅子或台阶，记录模型误差而不改判为标定成功。

### 第三步：标定与复核

1. 按教师布点测量四个坐标，记录卷尺读数。
2. 备份旧矩阵，运行 `--calibrate`，按指定顺序点击。
3. 若提示非凸四边形或残差异常，右键/R 清除后重新点击，不手动编辑 `.npy` 伪造通过。
4. 保存后再次运行 `--offline`，在 2～3 个已知位置检查反投影结果。
5. 记录相机是否移动、光照是否变化、人体是否完整入镜。任一条件改变后，先复核标定，再考虑 PID。

### 第四步：真机受控跟随

1. 完成安全检查，启动真机 GUI 并按 Space 准备移动模式。
2. 按 T 启动，先验证无目标立即停车。
3. 在悬挂/护架下小幅验证偏航方向，再验证短时前进/后退。
4. 观察并记录以下状态：目标丢失、视频帧过期、声纳数据超时/近障、目标过近、目标过远、看门狗提示。不能触发的项目用单元测试或教师离线演示补足，不为凑指标冒险制造真机故障。
5. 每次退出都检查跟踪按钮恢复“开始跟踪”，运动停止，随后再趴下/归零。

### 第五步：自动化安全测试

运行项目现有测试，不连接机器人：

```bash
python3 -m unittest discover -s tests -v
```

与 task12 直接相关的测试包括：

- 视频时间戳保留，断流错误使时间戳失效。
- 声纳使用原始状态帧龄，0.4 s 旧数据在 0.3 s 阈值下被拒绝。
- 后退、偏航小输出越过死区。
- 看门狗超时发送零轴、退出跟踪状态（恢复手动可用）并结束会话。
- 真机拒绝 dummy 文件名矩阵。
- 停止跟踪恢复手动模式；跟踪启动要求运动就绪；跟踪期间手动方向被禁用。

测试通过不代表真机安全已经验证；它证明相关逻辑在模拟条件下符合预期。

## 思考题

1. 为什么用检测框底边中点而不是框中心作为地面反投影点？哪些场景会破坏这个假设？
2. 四点标定为什么要求凸四边形和固定顺序？交换近左/近右会发生什么？
3. `--offline --dummy-h` 能验证什么，不能验证什么？
4. 偏航误差为什么用 `atan2(lateral, forward)`，而不是直接用像素横坐标误差？
5. 视觉帧龄 0.2 s、感知链路 0.5 s、看门狗 1.0 s、声纳帧龄 0.3 s 分别覆盖哪一段故障？
6. 为什么距离积分需要在死区外更新，并在停车时清零？
7. 死区抬升为什么能帮助后退和转向，却可能放大噪声？零值为什么仍必须保持零？
8. 目标过近时 `ONLY_TURN` 允许旋转，而 task10 的前后近障保护会把 yaw 也归零，两层保护应如何理解？

## 验收标准

### 离线与标定

- `--selfcheck` 七项断言全部通过，能解释偏航符号尚需真机确认。
- `--offline` 能显示人体框和脚点，不发送运动命令；`--dummy-h` 结果明确标注为非真实距离。
- 四点顺序正确，地面坐标用卷尺核实；标定残差最大不超过 0.005 m。
- 标定复核中能指出至少两种脚点不在地面或相机变化导致的误差来源。

### 安全逻辑

| 项目 | 验收要求 |
|---|---|
| 视觉帧龄 | 能说出 0.2 s 判据及无帧/负帧龄也停车 |
| 感知链路 | 能说出 0.5 s 超时；正常返回无目标仍由丢失规则停车 |
| 看门狗 | 能说出 1.0 s、0.05 s 检查周期及“退出跟踪状态（恢复手动可用）” |
| 声纳帧龄 | 使用原始 `state_age`，0.3 s 超时；不能靠读取刷新 |
| 声纳有效性 | 有限且大于 0；小于 1.0 m 阻塞、大于 1.3 m 恢复 |
| 视觉距离 | 过近 1.0/1.3 m 迟滞，过远 3.5/3.0 m 迟滞 |
| 目标丢失 | 当前实现立即停车，不是等待 10 帧 |
| PID 停车 | 非 active 时速度、角速度、积分与滤波状态清零 |
| 轴死区 | 非零小输出越过死区，零输入仍为零 |
| dummy | CLI、会话启动、文件名/数值检查三层拒绝真机使用 |
| 互斥 | 跟踪禁手动；停止跟踪后恢复手动 |
| 退出 | T/Esc/失焦/停止按钮均停运动并退出跟踪 |

### 真机表现

- 在悬挂/护架下确认偏航方向正确；方向反时立即停止，不盲目加大输出。
- 无目标时真机运动轴归零，日志显示“目标丢失，已停车”。
- 能完成一次短时、低速、受控跟随，无碰撞、无人员进入运动路径。
- 退出跟踪后手动控制恢复；最终按 Space 趴下并完成所需归零。
- 实验报告记录标定、离线输出、真机日志和安全退出过程，不只有截图。

## 常见错误

| 错误/现象 | 原因 | 处理 |
|---|---|---|
| selfcheck 报错或依赖导入失败 | 虚拟环境、依赖或资源不匹配 | 回到 WSL 项目环境检查，不进真机 |
| 离线无画面 | RTSP 地址、网络、FFmpeg 或相机连接异常 | 先检查视频线程错误，再检查 UDP |
| dummy 模式距离“很准” | 占位矩阵恰好符合简化画面 | 仍不得用于真机，必须真实标定 |
| 标定提示非凸四边形 | 点序交叉、点击错点或标记位置错误 | 右键/R 清除，按近左→近右→远右→远左重选 |
| 残差大于 0.005 m | 点选错误、坐标与实物不符、求解异常 | 重新测量布点并标定，不手动篡改矩阵 |
| 离线距离随姿态变化很大 | 脚点不在同一地面平面、相机移动、遮挡 | 固定相机、选择平整地面和完整人体后复核 |
| 真机拒绝 dummy | 安全设计生效 | 使用真实 `H.npy` 重新标定 |
| 偏航方向反 | 坐标约定或 `WZ_SIGN` 与真机不一致 | 立即停车，教师分析；课堂不改代码 |
| 一直停车并提示帧过期 | 视频卡顿、旧帧被重复读取或推理过慢 | 停止真机，先离线排查帧龄和性能 |
| 声纳值很大仍提示超时 | 数值存在但状态帧龄超过 0.3 s | 检查状态上报链路，不能读取刷新 |
| 无目标仍偶尔动一下 | 对锁定 ID 保留与安全层行为理解错误 | 核对当前 `check()`：无目标立即 STOP |
| 跟踪中方向键无效 | 手动/跟踪互斥 | 先按 T 或停止按钮退出跟踪 |
| 过近时仍前进 | 把 `ONLY_TURN` 误解为正常前进，或看错日志 | `ONLY_TURN` 必须 vx=0；检查实际轴值 |
| 关闭窗口后机器人站立 | GUI 关闭不自动趴下/归零 | 关闭前停止跟踪并按 Space 收尾 |
